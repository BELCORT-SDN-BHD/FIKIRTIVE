# 跑分档案

一条线一份：`engine.json`（缺省）、`creation.json`（`--line=creation` 跑出来的那一份）。

每份档案记：日期、commit sha、被测型号与判分型号、单次预算上限、**真实花费**、逐题分（含产物与每一条判词）、总分。
写档案的是 `pnpm --filter @fikirtive/otto run evals`（Creation 那份加 `-- --line=creation`）；
`evals:check` 只比对、不覆盖，而且**开跑前**就会发现「这条线还没有基线」并非零退出——不会白跑一趟。

档案是 git 跟踪的 —— 「不低于基线」这句话要有一个能 diff 的对象。

## `spend.jsonl` —— 花费账本（只追加，不覆盖）

一趟一行（JSON Lines）：`{"line","date","commit","costUsd"}`。**每成功跑一趟就追加一行**，
不管这趟是写档案还是 `--check`（两者都真的花钱）。

「本段累计 $20」这道闸读的是**它**，不是上面那两份档案：档案每跑一次就被整份覆盖，
拿它求和只算得到「每条线最后那一趟」——跑了三趟只记一趟的钱，累计就名不副实。
账本只追加，所以三趟就是三趟的钱。

**不要手改、不要重排、不要删行**：删掉一行等于把已经花掉的钱从闸上抹掉。
读不懂的一行会让 runner 当场炸（拒绝按 0 计），这是故意的。

首行是 2026-09-05 那一趟首跑（$0.46167）从 `engine.json` 补记的 —— 账本比它晚一天出生，
但那笔钱真的花了，不该因为账本后建就凭空归零。
