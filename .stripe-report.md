## CreditGrantSource check

`CreditGrantSource` in `packages/db/src/credits.ts` is `"ADMIN" | "BETA" | "PROMO" | "PURCHASE" | "SYSTEM"`. It does NOT include `"STRIPE"`. Used `"PURCHASE"` — semantically correct for a paid top-up.

## Env vars needed (not hardcoded)

- `STRIPE_SECRET_KEY` — Stripe secret key (server-side only)
- `STRIPE_WEBHOOK_SECRET` — webhook signing secret from Stripe dashboard
- `APP_URL` — canonical app URL (e.g. `https://app.fikirtive.com`) used for success/cancel redirect URLs

## Stripe apiVersion

Omitted `apiVersion` in the Stripe client constructor — SDK default is used. This avoids a compile error if the installed `stripe@^17` types don't export the `"2024-12-18.acacia"` literal. Stripe recommends pinning in prod; that can be done once the package is installed and the exact supported literal is confirmed.

## Testable vs needs-Stripe-keys

- **Testable now (pure):** `stripe-packs.test.ts` — no DB, no network, no Stripe. Run with `pnpm --filter @fikirtive/web exec vitest run lib/__tests__/stripe-packs.test.ts`.
- **Needs Stripe keys / network:** `createTopupCheckout` (calls `stripe.checkout.sessions.create`) and the webhook handler (calls `stripe.webhooks.constructEvent`). These are covered by the Stripe test-mode key + `stripe listen --forward-to` in dev/staging.

## Security properties

1. Webhook verifies Stripe signature before trusting any data; 400 on bad sig.
2. `metadata.orgId` is written server-side at checkout creation from the verified session — not user-supplied input.
3. `idempotencyKey: "stripe:<session.id>"` makes a replayed webhook a no-op (DB unique index on `(orgId, idempotencyKey)`).
4. `createTopupCheckout` is gated by `requireOwner()` — no unauthenticated or non-allowlisted access.
5. This is purely additive (grant path) — no change to reserve/settle/charge logic.

## Concerns / follow-ups

- `pnpm install` must run in CI before the build picks up `stripe@^17`.
- Add `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `APP_URL` to Vercel project environment variables.
- Register the webhook endpoint `POST /api/stripe/webhook` in the Stripe dashboard (test mode first, then live).
- Consider a `stripe listen --forward-to localhost:3000/api/stripe/webhook` script in the dev README for local testing.
- The `apiVersion` should be pinned to the value exported by the installed `stripe@^17` types once `pnpm install` has run.
