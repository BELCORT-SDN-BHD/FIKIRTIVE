## 2. SMB 视角(马来西亚/SEA 中小企业营销人真正用什么)

**SMB 常用(高频、真痛点):**
- **WhatsApp channel 进共享收件箱** — SEA 的绝对核心。马来西亚 SMB 的客服+销售+订单确认几乎都在 WhatsApp 上;HubSpot 这块反而弱(按模板消息计费贵、需 WABA、档位高)。
- Shared inbox / help desk 的**轻量形态**(几个人不漏消息、知道谁在跟谁)— 常用;但 HubSpot 的 spaces/views/macros 全套对 5 人团队过重。
- Live chat 挂件 + 简单 qualify/建单 bot — 常用(有网站的那部分 SMB)。
- Facebook Messenger + Instagram DM — 常用,MY 电商/餐饮/美容业标配。
- **AI 自动回复(Breeze customer agent 的等价物)** — 需求真实且爆发中;但 HubSpot 要 Pro($90+/席)+按次付费,SEA SMB 付不动。
- Payment links / 简单 invoice — 常用;MY 习惯 WhatsApp 发收款链接(但本地更常用 DuitNow/银行转账/本地网关 Billplz、iPay88,Stripe MYR 费率偏高)。
- 简单 ticket 状态(处理中/完成)— 用得上,但不叫"工单",就是"别忘了这个客户"。
- 联系人去重/格式清洗(data quality 的最小子集)— 隐性刚需,他们不知道自己要,直到名单乱掉。

**企业级(SEA SMB 基本不会用):**
- SLA 引擎(工作时间、conditional SLA)、skill-based routing、task queues — 需要有"客服部"才有意义。
- Customer portal、私有 KB+SSO、多知识库、多语言 KB。
- Customer success workspace / health scores / 续约管道 — B2B SaaS 专属。
- Datasets / Data Studio / Snowflake share / 数仓集成、programmable automation(写 JS/Python)— 有 RevOps 岗位才用得到。
- Conversation intelligence、coaching playlists、IVR、playbooks、goals。
- Customer journey analytics、100 个 dashboard。

**存疑(看客群):**
- NPS/CSAT 调研 — 多数 MY SMB 不做正式 NPS;但"会话结束后一条 WhatsApp 满意度小问"可能有价值。
- Knowledge base — 做公开 help center 的 SMB 少;但**作为 AI 自动回复的知识源**(喂 FAQ/价目表/政策)是刚需的另一种形态。
- Data sync(iPaaS)— SMB 用的是"接上我的 Shopify/Google Sheet",不是通用同步引擎。
- Subscriptions 循环扣款 — 健身房/补习班/订阅盒子类 SMB 有需求,其他没有。

## 4. HubSpot 的 Agent/AI 打法 vs FIKIRTIVE "Otto operates 100%"

**HubSpot 的打法(Breeze 体系):**
- **形态:一个 Copilot + 一堆单一职能 agent**。Breeze Assistant(免费问答助手)、Customer Agent(客服)、Prospecting Agent(销售外联)、Knowledge Base Agent(写 FAQ)、Data Agent(补数据)、Custom Agents(Ent 自建)([官方 AI 页](https://www.hubspot.com/products/artificial-intelligence))。每个 agent 是产品里**一个开关+一个配置页**,各管一段流程。
- **商业模式:统一 HubSpot Credits + 2026-04 起按结果计费**($0.50/解决的会话、$1/合格 lead、$0.10/数据答案),各档赠送 credits(500/3,000/5,000),加购 $10/1,000([官方公告](https://www.hubspot.com/company-news/hubspots-customer-agent-and-prospecting-agent-now-you-pay-when-the-task-is-complete))。这是行业首批"按 outcome 收 AI 费"的大厂,定价叙事对 FIKIRTIVE 有直接参考价值。
- **定位叙事:"hybrid teams"** — AI 处理量,人处理关系;agent 始终在人配置的边界内跑(选知识源、设转人工规则、审计报表)。

**他们做不到、FIKIRTIVE(Otto)能做的:**
1. **横向编排**:Breeze agents 各守一格 — customer agent 不会顺手去改广告、prospecting agent 不会去发内容。Otto 的命题是同一个 agent 操作 100% 工具(回消息→顺手建 campaign→生成素材→调预算),跨域一条链。
2. **操作全部 UI**:HubSpot 的 AI 只覆盖它被授权的那几个切面,其余 90% 的产品仍要人肉点;FIKIRTIVE 每个手动工具天生就是 Otto 的 skill(defineOttoSkill 框架),不存在"AI 够不着的角落"。
3. **配置负担**:Breeze 要 SMB 自己选知识源、配 routing、买 credits、看仪表盘 — 对无 ops 岗位的 MY SMB 仍太重。Otto 的"super-employee"叙事=开箱即用一个员工,不是一柜子开关。
4. **价格结构**:Breeze customer agent 要 Service Pro($90+/席/月)起步再加按次费;FIKIRTIVE 可以把"AI 客服"做成低门槛入口而非高档位特权。
5. **SEA 本地性**:WhatsApp-first、马来语/华语/Manglish 混语、本地收款习惯 — HubSpot 是美国中心的 email-first 产品。

**他们能做到、FIKIRTIVE 目前做不到的(诚实盘点):**
1. **9 渠道成熟接入**(WhatsApp/SMS/IG/Telegram/LINE/Slack/Messenger/email/chat+语音 beta)与 custom channel API — 渠道广度是多年的合规+基建积累。
2. **1,700+ app 生态 + data sync iPaaS** — 客户数据在哪都能进来。
3. **完整客服机器**(SLA、routing、portal、KB、CSAT)— 若 FIKIRTIVE 客户长大,会撞到这个天花板。
4. **Breeze Intelligence 数据资产**(全网公司画像、buyer intent)— 数据壁垒,短期无法复制。
5. **规模化信任**:约 8,000 客户上 customer agent、公开解决率基准(65%)([resolve247](https://resolve247.ai/blog/hubspot-breeze/))— FIKIRTIVE 需要自己的"Otto 解决率"证据链。
6. **免费 CRM 获客飞轮** — Free 档白送换生态锁定,FIKIRTIVE 的 credits 模型需要不同的获客故事。

**一句话情报总结**:HubSpot 正在把 AI 从"付费档特权"变成"按结果计费的用量商品",但其 agent 是**产品里的功能**;FIKIRTIVE 的差异化空位在于 agent 是**产品本身的操作员**——尤其在 HubSpot 定价和渠道打法都不为 SEA SMB 设计的市场里。
