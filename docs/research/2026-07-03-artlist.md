## 1. 产品定位一句话 + 定价模型

**一句话:** Artlist = 面向视频创作者的"一站式创意资产 + 生成式 AI 订阅平台"——授权音乐/SFX/8K 素材/模板/插件/LUT + AI 图片/视频/配音,核心卖点是**"一次下载,永久授权,平台不会给你打版权(covers-you licensing + Clearlist)"**;Artgrid = 同公司(Artlist 旗下)专注**电影级 stock footage(含 RAW/LOG/ProRes)**的子品牌。

**定价模型(2026,均以年付月均价呈现,月付更贵;多数计划强制年付):**
- 分层混搭:先选"素材目录"(Music/SFX/Footage&Templates)或"AI Suite"(按 credits 分档),或用 **Artlist Max** 一价打包全部。
- Artlist 关键档(年付月均):
  - **Music & SFX Social** ~$9.99(Social license,单平台单频道)
  - **Music Pro** ~$16.58 / **Music & SFX Pro** ~$24.92(Pro license,3 频道 + 客户活)
  - **AI Voiceover** ~$11.99;**AI Starter** ~$13.99(7,500–16,500 credits/月);**AI Professional** ~$99.99(180,000–1,000,000 credits/月 + 优先队列)
  - **Footage & Templates** ~$31.99(8K + 模板 + LUT;RAW/LOG 加购 ~$17.93)
  - **Artlist Max** ~$39.99(全部素材 + AI + 50+ 插件;升到 180,000+ credits 解锁 5 个免费 team seat)
  - **Teams**(≤50 人非代理):Music Teams ~$14.08/人、Music&SFX Teams ~$21.17/人、Max Pro Teams ~$33.99/人;**Max Business**(50+ 人 / 任意规模代理,custom)含 legal indemnification + admin 控制;**Enterprise**(custom,SSO + 高级安全)
- Artgrid 独立三档(强制年付、无限下载):**Junior** $19.99/月($239.90/年,H.264)/ **Creator** $29.99/月($359.90/年,4K–8K + ProRes/DNxHR + graded)/ **Pro** $49.92/月($599/年,+ RAW/LOG)。
- **核心经济学:** 授权是"universal + perpetual"——订阅期内下载的资产,退订后仍可永久用于当时的项目。这是它区别于 per-track 买断的最大商业机制。

## 3. SMB / SEA 视角(马来西亚/东南亚 SMB 真会用 vs 企业虚胖)

**SEA SMB 真会用(高相关):**
- **Universal + perpetual license**——SMB 最怕的就是"用了音乐被打版权/被 demonetize / 客户来问授权",这直接消除焦虑,是 SEA 中小商家/自由职业者的真痛点。
- **Clearlist(自动清版权)**——马来西亚做 TikTok/IG/YT 带货的 SMB 极度受益;"报备一次永久清除"符合他们的心智。
- **AI Video/Image/Voiceover + credits 起步档(~$14/月)**——低价试水生成式,SEA 成本敏感,起步档 credits 够跑几十条短视频。
- **AI Voice Clone + 多语言本地化**——SEA 多语言(马来语/华语/英语/泰语)市场,一次录音多语言配音是刚需。
- **Premiere/编辑器内拖拽 + Artboards 分享给客户**——本地小代理/接单党真实工作流。
- **License Certificate PDF**——给客户交付时附授权凭证,SMB 拿单的信任凭据。

**企业虚胖(SEA SMB 基本用不上):**
- **SSO / 高级安全 / Enterprise custom**——50+ 人 + 全球分发才需要,SEA SMB 无关。
- **Cue Sheets(广播/OTT 元数据)**——只服务电视台/发行,SMB 不碰。
- **Team Credit Usage dashboard / model controls**——多人代理才有意义;单人/2-3 人 SMB 过度。
- **RAW/LOG / ProRes / DNxHR / 8K**——多数 SEA SMB 交付 1080p/4K 社媒,RAW 工作流是电影级虚胖(接高端商单的少数除外)。
- **50+ 专业插件**——重度后期才吃得下,SMB 大多只用素材+模板。

## 4. FIKIRTIVE feature 候选映射(WHAT-pass 候选,中立呈现利弊)

> 支柱对照:内容创作 / CRM / 回复管理 / **资产库** / 效果营销;founder 优先级 = 安全 > 效率 > 易管理。

| Artlist feature 簇 | 判断 | 进哪个支柱/区 | 利 | 弊 / 存疑 |
|---|---|---|---|---|
| **Universal + perpetual license 模型** | 存疑(定位差异) | — | 概念上"一次生成永久可用"很干净 | Artlist 是"授权别人的版权";FIKIRTIVE 生成的是**用户自有产出**,授权语义不同——照搬会混淆。可借鉴的是"清晰告诉用户这资产能用在哪"的确定性,而非授权层本身 |
| **Clearlist(平台报备/防版权 claim)** | 建议不要(短期) | — | 对纯授权曲库是杀手锏 | FIKIRTIVE 用生成资产,不面对第三方版权 claim;是解一个 FIKIRTIVE 没有的问题 |
| **Artboards(项目级资产聚合 + AI 推荐 + 分享链接)** | **该进 —— 资产库区(My Stuff/Library)** | 资产库 | 直接对应 founder 想要的"资产区";把散落生成物按"项目/campaign"聚合 + 可分享给客户,是 marketing OS 的自然形态 | 需决定"项目"是不是 FIKIRTIVE 的一等对象(与 canvas/otto task 的关系) |
| **Collections / Favorites** | **已有雏形 / 该强化** | 资产库(My Stuff) | 低成本、高频、非技术用户友好 | 与现有 canvas node / My Stuff 去重 |
| **Search & Filtering(多维 facet:mood/genre/shot type/BPM)** | **该进 —— 资产库检索** | 资产库 | 资产多了必需;facet 化检索是"易管理"的关键 | FIKIRTIVE 资产的 facet 是什么(平台/campaign/品牌/生成模型/日期?)需先定元数据 |
| **License Certificate / 授权凭证 PDF** | 存疑 | 资产库 or 效果营销 | 交付客户时的信任凭据;SEA 接单党真会用 | FIKIRTIVE 生成物的"授权"语义待定;可能变成"AI 生成声明"而非授权证 |
| **AI Image/Video/Voiceover(生成)** | **已有(Otto/canvas 生成)** | 内容创作 | FIKIRTIVE 已在做 | 无需新增;参考的是它的**打包/credits 呈现**而非能力 |
| **Credits 机制(共享池 + 不滚存 + 升档滚存例外 + Team Credit dashboard + model controls)** | **该进 —— 效果/账户管理** | 账户/管理区 | FIKIRTIVE 已是 credit 经济;Artlist 的"共享池 + admin 可见性 + per-model 控制"是成熟范式 | 与现有 grantCredits/spend-path 对齐;model controls 是新面(admin 限制团队可用模型) |
| **AI Voice Clone + 多语言本地化** | **该进(SEA 高价值)** | 内容创作 | SEA 多语言市场刚需;差异化 | 成本/合规(声音克隆同意)需谨慎——碰 founder 第 1 优先级"安全" |
| **Premiere/编辑器内拖拽 extension** | 建议不要 | — | 对桌面剪辑党有用 | FIKIRTIVE 是 Otto-operator web app,不是插桌面 NLE 的场景 |
| **50+ Plugins / LUTs / RAW-LOG / ProRes** | 建议不要 | — | 电影级后期 | 与 FIKIRTIVE 定位(SMB agentic marketing)不符,重度虚胖 |
| **Team seats + admin controls + SSO** | **该进(渐进)** | 账户/运营控制台 | 与已有 operator console / Better Auth admin 对齐 | 分阶段;SEA SMB 早期用不到 SSO |
| **Collaborative Artboards(团队协作板 + 客户反馈无需账号)** | **该进(中期)** | 资产库 + CRM 交叉 | "分享给客户拿反馈"直连 marketing OS 的 CRM/回复支柱 | 需协作/权限模型;中期非首发 |
| **Stock 素材目录(音乐/SFX/footage 授权库)** | **明确不要** | — | Artlist 的核心业务 | FIKIRTIVE 不做版权授权分销;这是完全不同的业务 |

## 5. 值得偷的 feature 机制(具体、聪明、FIKIRTIVE 该借鉴)

1. **Artboards = "项目容器 + AI 荐料 + 免账号分享"三合一。** 最聪明的是它把"资产组织"从静态文件夹升级成**围绕一个 campaign/项目的活工作区**,还能"按项目描述让 AI 推荐要加什么资产",并生成**无需对方注册**的分享链接收反馈。FIKIRTIVE 资产区若照此设计,天然把"资产库 × 内容创作 × CRM 反馈"三支柱串起来。

2. **Credits 共享池 + "不滚存,但升档首月例外"的精确规则。** 一个池覆盖图/视频/配音,规则极简可解释;"升档滚存"是聪明的**升级激励**(降低用户对"这月没用完"的损失厌恶)。FIKIRTIVE credit 经济可直接借这条升级心理。

3. **Clearlist 的"报备一次,永久清除"心智。** 抛开版权本身,值得偷的是**把一个持续性的焦虑,一次性动作永久解决**的产品化——FIKIRTIVE 可类比:某个"发布安全/品牌合规检查",做成"设定一次,之后自动保护",契合 founder"安全"+"易管理"。

4. **License Certificate / 授权凭证 PDF 作为交付信任物。** SEA 接单党给客户交付时,一份"这资产你可以合法用"的凭证是拿单信任杠杆。FIKIRTIVE 可做"AI 生成声明 / 使用范围凭证",作为交付资产的附带信任物。

5. **Team Credit Usage dashboard + per-model 控制。** admin 能看全员 credits 消耗 + 限制可用模型——这正是 founder 第 3 优先级"易管理"的教科书:**把复杂的花费/模型选择,收敛成 admin 一处可见 + 可开关的面板。**

## 6. 易管理视角(对齐 founder 第 3 优先级:file-system 风格,可读文件 + 简单开关)

Artlist 让非技术用户管理复杂功能的聪明做法,对 FIKIRTIVE 的启发:

- **分层混搭定价 → 一价打包(Max)的"逃生舱"。** 复杂的多档组合让高级用户精调,但给不想选的人一个 Artlist Max"全都要"的单一选择。**对 FIKIRTIVE:** 高级 admin 可细调每功能,但永远留一个"推荐默认全开"档,避免非技术 founder 陷入配置泥潭。

- **Artboards = 用"板"这个直觉容器隐藏组织复杂度。** 用户不用理解标签/元数据体系,只需"把东西丢进这块板"。**对 FIKIRTIVE 资产区:** 用"项目/campaign 板"作主组织单元,比强迫用户建文件夹树更易管理。

- **License 用"一句话规则"表达复杂法律。** "订阅期下载的,永久能用"——把授权律师条款压成一句可读心智。**对 FIKIRTIVE:** 每个开关/功能配一句"这会/不会花钱、能用在哪"的人话说明,而非埋在条款里。

- **Credits 单一共享池 + 单一 dashboard。** 不给用户三个独立配额去管理,而是一个池 + 一个消耗视图。**对 FIKIRTIVE:** 花费管理收敛成"一个 credit 池 + 一个 admin 可见面板 + per-model 开关",正是 founder 想要的"可读 + 简单开关",而非把控制埋进多处设置。

- **per-model controls 作为 admin 的"简单开关"。** admin 用开关决定团队能用哪些贵/便宜模型——把"成本治理"变成一排 toggle,而非改代码/改预算逻辑。这与 memory 里 founder"安全 > 效率 > 易管理、file-system 风格"高度一致,且不碰 spend-path 逻辑本身(只是准入开关)。
