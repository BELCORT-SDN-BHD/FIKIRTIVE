Assumption: this critiques the current as-built M0 flow, not the intended roadmap.

**1. Core Diagnosis**

Fikirtive’s biggest structural UX problem is that the creator, not the product, is the workflow engine.

The product has strong pieces: global Elements, @mentions, reference health, shot cards, upload provenance, and a real MP4 editor. But the central object a creator needs, “this shot generation attempt using these locked references against this target, producing these candidates,” is missing from the UI. So the flow becomes: manage references in one room, write/copy a prompt in another, render elsewhere, upload back, manually attach, then switch to editor.

Evidence:

- Navigation splits the production loop into `Workbench`, `Editor`, and global `Elements` rather than one continuous creation surface: [AppShell.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/AppShell.tsx:106).
- The Workbench empty state sends users away to Library before they can meaningfully create: [Workbench.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Workbench.tsx:122).
- The composer’s main action is still `Copy resolved prompt`, with an inert `Target · ComfyUI manual` chip: [Composer.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Composer.tsx:392).
- Returned outputs land as `Unattached` history and require manual attach/drag: [Workbench.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Workbench.tsx:160), [Workbench.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Workbench.tsx:367).
- The editor only sees the latest attached render per shot: [page.tsx](/Users/winnin/Documents/fikirtive/apps/web/app/editor/page.tsx:31). No attachment, no film.

LTX’s useful lesson is not the suite sprawl. It is the stable composer shell: references, prompt, params, validation, and target live at the point of action ([ltx-ux-comparison.md](/Users/winnin/.gstack/projects/fikirtive/research/ltx-ux-comparison.md:89)). Fikirtive has the components, but not yet the loop.

**2. The Broken Seams**

Creator goal: “I want to make a video ad.”

- **Project start:** New project is just a shot board. There is no ad brief, platform, duration, product objective, or target audience. “Plan the film shot by shot” is generic film language, not creator/ad language: [Workbench.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Workbench.tsx:125).
- **Reference setup:** Elements are powerful, but creating them requires leaving the Workbench. The @mention dropdown dead-ends with “create one in the Library” instead of letting the user create inline: [Composer.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Composer.tsx:71).
- **Generate refs inconsistency:** `CreateDialog` says Generate refs will produce a prompt to render in ComfyUI: [Library.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Library.tsx:344). But the detail drawer actually generates references in-app via Seedream/fal with price and polling: [Library.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Library.tsx:418). That is a real UX contradiction.
- **Prompting:** @mentions work well, and blocking copy for missing references is correct: [Composer.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Composer.tsx:332). But “resolved prompt” resolves mostly to text/name, not a portable reference pack with images, notes, negatives, target metadata, and a ComfyUI-ready manifest: [Composer.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Composer.tsx:112).
- **External render:** The user copies text, leaves Fikirtive, renders in ComfyUI, then remembers to return. The `Target` chip names the handoff but does not operationalize it.
- **Return/upload:** Upload preserves selected-shot prompt/entity provenance: [Workbench.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Workbench.tsx:425). But it still drops the user into an “Unattached” mental model instead of “candidates for Shot 02.”
- **Selection:** Candidate review is really file management. “Attach to shot…” is an implementation action; the creator action is “use this take.”
- **Editor handoff:** Editor starts from attached latest renders only and shows “Nothing to cut yet” otherwise: [Editor.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Editor.tsx:247). This makes attach the hidden gate to MP4.
- **Export:** Export exists, but `Target · worker ffmpeg` is engineering language: [Editor.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Editor.tsx:299). The user should see “MP4 render,” not infrastructure.

**3. Optimized Flow**

**Workbench: Campaign Board**

Start with one screen for the ad: project brief, shot list, active shot, candidate tray, and composer. Library remains available, but not required before creation.

**Inline Element Creation**

Typing `@Maya` with no match should offer `Create @Maya` inline. The modal should ask: Character / Location / Product / Brand, then Upload refs or Generate refs in Fikirtive. No separate Library trip for the happy path.

**Composer As Control Center**

Use a three-band composer:

- Top: reference strip showing mentioned entities, thumbnails, missing-ref warnings, roles, and reference count.
- Middle: prompt text with @chips.
- Bottom: target/actions. Today: `Manual ComfyUI` with `Prepare pack`, `Copy prompt`, `Download refs`. Later: connected fal/BYO targets with `Generate`.

**Shot Runs**

Every time the user prepares or generates, create a visible “run” under the selected shot: prompt, refs, target, time, status, candidates. Manual ComfyUI can be `Awaiting upload`; connected fal can be `Generating`.

**Candidate Review**

Returned files should default into `Shot 02 candidates`, not `Unattached`, when a shot is selected. Primary action: `Use take`. Secondary: compare, discard, move to another shot.

**Editor**

Editor should read selected takes from the board and show sync state: “12 selected takes from board.” Replace `Reset to board` with a non-destructive `Update from board` diff. Export remains simple: Save cut, Export MP4, Download.

**Library**

Library becomes the global Reference Registry: manage aliases, refs, notes, negatives, variants, and usage. It should also have “Add to current shot” when a project/shot context exists.

**5. Wedge Protection**

Do not become LTX.

Fikirtive’s protected wedge is not “AI video studio.” It is the model-neutral reference layer for creators who use many generation tools.

Protect that by keeping these boundaries:

- References stay free; generation is where monetization lives.
- Global entity library remains core; do not bury it inside project-only assets.
- Manual ComfyUI is first-class, not a temporary embarrassment.
- Connected fal/BYO targets should be adapters to the same reference/prompt/run system.
- Entity edits should affect future runs, not mutate history.
- Avoid LTX-style suite sprawl: no separate Gen Space, Canvas, Storyboard, Flows clone.

**1. Core Diagnosis**

Fikirtive’s biggest structural UX problem is that the creator, not the product, is the workflow engine.

The product has strong pieces: global Elements, @mentions, reference health, shot cards, upload provenance, and a real MP4 editor. But the central object a creator needs, “this shot generation attempt using these locked references against this target, producing these candidates,” is missing from the UI. So the flow becomes: manage references in one room, write/copy a prompt in another, render elsewhere, upload back, manually attach, then switch to editor.

Evidence:

- Navigation splits the production loop into `Workbench`, `Editor`, and global `Elements` rather than one continuous creation surface: [AppShell.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/AppShell.tsx:106).
- The Workbench empty state sends users away to Library before they can meaningfully create: [Workbench.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Workbench.tsx:122).
- The composer’s main action is still `Copy resolved prompt`, with an inert `Target · ComfyUI manual` chip: [Composer.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Composer.tsx:392).
- Returned outputs land as `Unattached` history and require manual attach/drag: [Workbench.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Workbench.tsx:160), [Workbench.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Workbench.tsx:367).
- The editor only sees the latest attached render per shot: [page.tsx](/Users/winnin/Documents/fikirtive/apps/web/app/editor/page.tsx:31). No attachment, no film.

LTX’s useful lesson is not the suite sprawl. It is the stable composer shell: references, prompt, params, validation, and target live at the point of action ([ltx-ux-comparison.md](/Users/winnin/.gstack/projects/fikirtive/research/ltx-ux-comparison.md:89)). Fikirtive has the components, but not yet the loop.

**2. The Broken Seams**

Creator goal: “I want to make a video ad.”

- **Project start:** New project is just a shot board. There is no ad brief, platform, duration, product objective, or target audience. “Plan the film shot by shot” is generic film language, not creator/ad language: [Workbench.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Workbench.tsx:125).
- **Reference setup:** Elements are powerful, but creating them requires leaving the Workbench. The @mention dropdown dead-ends with “create one in the Library” instead of letting the user create inline: [Composer.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Composer.tsx:71).
- **Generate refs inconsistency:** `CreateDialog` says Generate refs will produce a prompt to render in ComfyUI: [Library.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Library.tsx:344). But the detail drawer actually generates references in-app via Seedream/fal with price and polling: [Library.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Library.tsx:418). That is a real UX contradiction.
- **Prompting:** @mentions work well, and blocking copy for missing references is correct: [Composer.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Composer.tsx:332). But “resolved prompt” resolves mostly to text/name, not a portable reference pack with images, notes, negatives, target metadata, and a ComfyUI-ready manifest: [Composer.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Composer.tsx:112).
- **External render:** The user copies text, leaves Fikirtive, renders in ComfyUI, then remembers to return. The `Target` chip names the handoff but does not operationalize it.
- **Return/upload:** Upload preserves selected-shot prompt/entity provenance: [Workbench.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Workbench.tsx:425). But it still drops the user into an “Unattached” mental model instead of “candidates for Shot 02.”
- **Selection:** Candidate review is really file management. “Attach to shot…” is an implementation action; the creator action is “use this take.”
- **Editor handoff:** Editor starts from attached latest renders only and shows “Nothing to cut yet” otherwise: [Editor.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Editor.tsx:247). This makes attach the hidden gate to MP4.
- **Export:** Export exists, but `Target · worker ffmpeg` is engineering language: [Editor.tsx](/Users/winnin/Documents/fikirtive/apps/web/components/Editor.tsx:299). The user should see “MP4 render,” not infrastructure.

**3. Optimized Flow**

**Workbench: Campaign Board**

Start with one screen for the ad: project brief, shot list, active shot, candidate tray, and composer. Library remains available, but not required before creation.

**Inline Element Creation**

Typing `@Maya` with no match should offer `Create @Maya` inline. The modal should ask: Character / Location / Product / Brand, then Upload refs or Generate refs in Fikirtive. No separate Library trip for the happy path.

**Composer As Control Center**

Use a three-band composer:

- Top: reference strip showing mentioned entities, thumbnails, missing-ref warnings, roles, and reference count.
- Middle: prompt text with @chips.
- Bottom: target/actions. Today: `Manual ComfyUI` with `Prepare pack`, `Copy prompt`, `Download refs`. Later: connected fal/BYO targets with `Generate`.

**Shot Runs**

Every time the user prepares or generates, create a visible “run” under the selected shot: prompt, refs, target, time, status, candidates. Manual ComfyUI can be `Awaiting upload`; connected fal can be `Generating`.

**Candidate Review**

Returned files should default into `Shot 02 candidates`, not `Unattached`, when a shot is selected. Primary action: `Use take`. Secondary: compare, discard, move to another shot.

**Editor**

Editor should read selected takes from the board and show sync state: “12 selected takes from board.” Replace `Reset to board` with a non-destructive `Update from board` diff. Export remains simple: Save cut, Export MP4, Download.

**Library**

Library becomes the global Reference Registry: manage aliases, refs, notes, negatives, variants, and usage. It should also have “Add to current shot” when a project/shot context exists.

**5. Wedge Protection**

Do not become LTX.

Fikirtive’s protected wedge is not “AI video studio.” It is the model-neutral reference layer for creators who use many generation tools.

Protect that by keeping these boundaries:

- References stay free; generation is where monetization lives.
- Global entity library remains core; do not bury it inside project-only assets.
- Manual ComfyUI is first-class, not a temporary embarrassment.
- Connected fal/BYO targets should be adapters to the same reference/prompt/run system.
- Entity edits should affect future runs, not mutate history.
- Avoid LTX-style suite sprawl: no separate Gen Space, Canvas, Storyboard, Flows clone.
- Avoid opaque credits and teaser chrome.
- Prefer “portable reference pack” over “closed video generator.”

The product should feel like: “Lock your cast, products, places, and brand once; send them to any model; keep every shot traceable.” That is distinct, useful, and defensible.
