## 1. 产品定位一句话 + 定价模型

**一句话定位**:Canva 已从"人人可用的设计工具"升级为自称的 **Creative Operating System(创意操作系统)**——从设计、协作、发布到广告投放效果全链路,2026 年 4 月更宣布"从带 AI 功能的设计平台,变成带设计工具的 AI 平台"(Canva AI 2.0)。250M+ 用户、190 国、47B+ 设计。([Creative OS 发布](https://www.canva.com/newsroom/news/creative-operating-system/)、[Canva AI 2.0](https://www.canva.com/newsroom/news/canva-create-2026-ai/))

**定价模型(重点:他们怎么收钱)**:
- **Freemium + 按席位订阅** 为主轴,**AI 用量以 credit 封顶**做增购杠杆,再加 **Print 电商**和**创作者抽成生态**:
  - **Free**:永久免费,25 万+ 免费模板、5GB 存储、基础 AI(如 Magic Media 视频生成仅 5 个**终身** credit)。([定价页](https://www.canva.com/en/pricing/)、[credit 限额](https://fluxnote.io/guides/canva-magic-media-limitations))
  - **Pro**:US$15/月(US$120/年),单人。解锁全部高级模板/1 亿+ 素材、1TB、Brand Kit、Magic Studio 全套,**约 500 AI credits/月**(全 AI 功能共享一个池)。([costbench](https://costbench.com/software/design/canva/)、[eesel 分析](https://www.eesel.ai/blog/canva-ai-pricing))
  - **Business**(2025-10 由 Teams 改名重发布):US$20/人/月,无最低席位;= Pro + 团队协作 + **Canva Grow Insights(Meta 广告创意分析)** + 更高 AI 用量 + Leonardo.Ai Essential + Flourish Presenter 捆绑 + GA/Salesforce/HubSpot 数据连接器 + Print 九折。旧 Teams 停止新签。([Business 发布](https://www.canva.com/newsroom/news/introducing-canva-business/))
  - **Enterprise**:询价(第三方估 $20k–50k/年),SSO/SCIM/审计日志/多级审批/无限 Brand Kit/Team Context。([CloudEagle](https://www.cloudeagle.ai/blogs/canva-pricing-guide))
  - **AI Pass 加购**:US$100/人/月,AI 用量放大 40x(Pro)/20x(Business)——**AI 重度用户单独收割**。([spendhound](https://www.spendhound.com/marketplace/canva-pricing))
  - **马来西亚本地价**:Pro 个人约 **RM250/年**(涨价前 RM249.90),旧 Teams 曾为 RM690/年/3 人(未核实是否仍在售);支持 FPX/GrabPay/信用卡。([says.com 涨价报道](https://says.com/my/tech/canva-price-increase-ai)、[BigGo MY](https://my.biggo.com/s/canva+pro/))
- **要点**:钱主要收在"席位 + AI credit 天花板",不按单次生成计价;视频生成 credit 非常抠(Pro 每月约 50 个视频 credit、每段 4 秒)——**AI 视频他们也不敢按成本敞开卖**,与 FIKIRTIVE"video 按成本卖、利润在 Otto"判断互相印证。

## 3. SMB 视角:马来西亚/东南亚 SMB 真会用的 vs 企业级虚胖

**真会用(观察 + 评测佐证)**:
- 模板 + 素材库(日常起稿的第一入口,BM/多语模板齐全)
- Background Remover、Magic Resize(一稿转 IG/FB/TikTok 尺寸)、Magic Eraser——**"设计急救包"三件套**
- Magic Write 写 caption(100+ 语言,含马来语)
- Magic Translate:**EN/BM/中文三语市场刚需**,134 语言保版式直翻
- Content Planner 轻量排期(单店主够用,但格式短板明显)
- Canva Print(MY 本地印名片/传单/菜单,线下生意刚需)
- Bulk Create(餐牌/价格卡/多 SKU 促销图,进阶用户)
- 本地支付 FPX/GrabPay + RM 定价:**付费摩擦已解决,SMB 早已在付**

**企业级虚胖(MY SMB 基本不碰)**:
- Enterprise 全家桶:SSO/SCIM/审计日志/多级审批/100+ Brand Kit/Team Context
- Canva Sheets 的 Snowflake/Statista 连接器;Flourish 交互数据可视化
- Canva Code、Websites(有免费建站替代)、Whiteboards(用的是 FB Messenger 和 WhatsApp 开会)
- Doohly 户外广告、Affinity 专业套件(设计师向,非商家向)
- AI Pass US$100/月(比 Pro 贵 6 倍,SMB 不会买)
- **Canva Grow:SEA 根本没上线**——MY SMB 现在享受不到,这是 FIKIRTIVE 的窗口而非现实威胁

## 4. FIKIRTIVE 候选映射(仅候选,决定权在创始人)

| Canva 功能簇 | 候选去向 | 权衡(中立呈现) |
|---|---|---|
| Magic Media / Dream Lab / Veo 3(AI 图/视频生成) | **已有对应楼**(创作区:Seedream/Seedance + canvas 4-variant 流) | FIKIRTIVE 走生成优先 + credit 计价;Canva credit 更抠(视频 4 秒/段)。无需追加,保持成本优势叙事即可 |
| 模板生态(数十万 UGC 模板) | **建议不要**(正面竞争)/ 存疑(垂直薄层) | 模板是 Canva 十年 UGC 飞轮,追不上;替代路线 = Otto 按品牌记忆直接生成"等效于模板"的成稿。若要,做 MY 行业垂直薄模板层(raya 促销/mamak 菜单)即可 |
| Brand Kit + Brand Guidelines | **资产区**(品牌记忆已在规划) | 值得对齐的是"资产 + 用法说明 + 生成时自动遵守";FIKIRTIVE 优势:Brand Kit 喂 Otto 而不只是喂人 |
| Brand Controls + Design Approvals | **资产区 / Agency 楼层** | 审批门槛与 FIKIRTIVE 既有 plan-approval/SoD 模式同构;Agency 楼层做多客户品牌隔离时几乎必备 |
| Magic Resize / Magic Switch(一稿多尺寸) | **创作区** | SMB 最高频刚需之一;FIKIRTIVE 生成侧可"按平台批量出多尺寸变体"原生解决,不必做像素级 resize 编辑器 |
| Magic Translate(134 语言保版式) | **创作区** | MY 三语市场高价值;FIKIRTIVE 可做 caption+创意的 EN/BM/中文一键三版,比 Canva 更贴本地(Manglish 语感) |
| Magic Write | **已有对应楼**(Otto 文案本来就是核心) | — |
| Bulk Create(数据→批量出图) | **创作区 / 存疑** | 多 SKU 商家有真实需求;但 FIKIRTIVE 版应是"Otto 读商品表批量生成",而非 CSV 映射 UI。做不做取决于电商类客户占比 |
| Content Planner(原生排期) | **排期区**(已规划 Buffer-like Schedule 页) | Canva 的弱点(无 Reels/Stories/轮播、caption 不分平台、浅分析)正是 FIKIRTIVE 排期区的超越清单 |
| Canva Grow 2.0(广告全链路) | **Campaign 管理区**(G7 v1/v2 已建 Meta ad-write/build) | **最直接的战略碰撞**。Grow 只在 NA/AU/UK;FIKIRTIVE 已有 Meta 写/建能力 + SEA 在地。Grow 的 auto-refresh(效果→自动出下轮素材)是值得追平的闭环 |
| Grow Insights / Sheets+Magic Charts+Insights | **分析区** | 分析区(规划中 ads+organic+history)对齐即可;Sheets 通用表格 = 建议不要,超出营销 OS 范围 |
| Email Design + Ortto(邮件/CDP/自动化) | **CRM 区 / 存疑** | 信号:Canva 正在买齐 CRM+自动化,证明"营销 OS 终局"判断;但 MY SMB 沟通主场是 WhatsApp 不是 email——FIKIRTIVE 的 CRM 区/自动回复区押 WhatsApp 可能是更对的本地化,email 可后置 |
| Docs / Presentations / Whiteboards / Forms / Code / Websites | **建议不要**(大部分)/ Websites 存疑 | 通用生产力是 Canva 对 Adobe/Microsoft 的战线,不是营销 OS 的必需;唯落地页(link-in-bio/campaign page)与广告转化相关,存疑后议 |

## 5. 他们的 AI/agent 打法 vs Otto-operates-100% 的差异化空间

**Canva 的打法**(2026-04 后):Canva AI 2.0 = 对话式 agent + 持久记忆 + 后台定时任务 + 外部 connectors + "自动调用对的工具"。方向上和 Otto 惊人地同向——**他们也在做 super-employee**。并且 Design Model 已输出到 ChatGPT/Claude/Gemini。

**但结构性差异(= FIKIRTIVE 的空间)**:
1. **操作面覆盖不同**:Canva 的 agent 只能操作"创意生产面"(设计/内容/局部广告)。排期浅、无 CRM、无客户对话/自动回复、广告只到 Meta/TikTok/LinkedIn 投放层且 **SEA 不可用**。Otto 的宪法是"每个楼层 100% 可被 agent 操作"——包括回消息、管客户、花钱投放(带审批门)。Canva 卖的还是"更聪明的工具";FIKIRTIVE 卖"工具 + 会用全部工具的员工"。
2. **钱的动作**:Canva Grow 自动 refresh 素材,但"agent 替你花广告预算"这一步他们没碰(也不敢,体量太大)。FIKIRTIVE 的 SoD + plan-approval + 花钱前确认,恰好是能安全走进这一步的架构。
3. **地理窗口**:Grow 2.0 限 NA/AU/UK;Ortto 独立运营未整合。**SEA 的"创意→投放→效果"闭环现在是空的**,FIKIRTIVE G6/G7 已经在 prod。
4. **本地纵深**:Canva 的本地化 = 语言翻译;FIKIRTIVE 可做 BM/Manglish 语感、raya/双十一节奏、FPX 级本地体验、WhatsApp 主场。
5. **风险面**:别低估——Canva 有 MY SMB 的既有付费关系和日常打开率;一旦 Grow 开 SEA + Ortto 整合,重叠面会很大。FIKIRTIVE 不该赌"Canva 做不到",该赌"Canva 做到那天,我们已经是那个客户离不开的 super-employee,而不是又一个工具"。

## 6. 值得偷的设计(他们做得特别聪明的机制)

1. **Brand Kit 作为"生成约束层"而不只是素材夹**:资产 + 每个资产的用法说明(Brand Guidelines)+ 硬管制(只许品牌色/字体)+ 审批门,层层递进、每层单独开关——和创始人"file-system 式、可读文件 + 简单 toggle"的管理哲学同构。FIKIRTIVE 资产区可以照此分层:资产 → 用法说明(喂 Otto)→ 硬约束 → 审批。
2. **一稿多尺寸(Magic Resize/Switch)作为默认动线**:Canva 把"create once, publish everywhere"做成一个按钮而不是一个功能页。FIKIRTIVE 创作区出图时就该默认产出"目标平台全尺寸套装",让用户从不需要想尺寸这件事。
3. **Grow 的效果反哺闭环**:读广告账户实际表现 → AI Ad Tagging 打结构化标签 → 解释"为什么这条有效" → **自动预生成下一轮素材**。这是"分析区→创作区"的自动回路,Otto 跨楼层操作恰好比 Canva 更适合做全量版(不只广告,连 organic 和回复话术都能反哺)。
4. **AI credit 阶梯 + AI Pass 收割**:免费档给"终身 5 次"制造饥饿、Pro 给月度池、重度用户单卖 $100/月 AI Pass——用量分层不碰基础订阅价。验证了 FIKIRTIVE credit 模型方向,也提示可研究"重度档"上探空间(与 40-50% margin 目标兼容)。
5. **Bulk Create 的 Auto-match**:数据字段自动映射到设计占位符,把"批量"从技术活变成拖拽活。若做电商批量生成,"Otto 自动对齐商品表字段"是同一招的 agent 化版本。
