### F12 · ad-build 越权(唯一 verdict 翻转:run1=CONFIRMED/P1,run2=REFUTED)

**事实两轮一致**:`apps/web/lib/meta-build-actions.ts` 顶部是 `"use server"`,`runAdBuild(ownerId,cardId)` 和 `maybeAutoBuild(ownerId,cardId)` 都接受调用方传入的 ownerId 且**没有** requireOwner 校验(文件自己的注释就写了 "does NOT re-authenticate")。

**分歧点**:能不能被普通登录用户 POST 出去。
- **run1(CONFIRMED)**:`"use server"` 模块的每个 export 都是公开 server-action 端点,理论上可构造 `Next-Action` 头 POST。
- **run2(REFUTED,技术更扎实)**:这两个函数**从未被任何 client 组件 import**(client 只碰 otto-client-actions.ts 里 requireOwner-gated 的 approveAdBuild/launchAdDraft 包装),所以 Next.js 16.2.9 不会给它们生成 client 可见的 action id;而 action id 用服务端密钥加盐(serverReferenceHashSalt),浏览器拿不到、也推不出——**没有可 POST 的端点**。

**裁定**:偏向 run2——当前**不可达**,不是活体越权(所以没进 P1 榜的「真风险」)。但它是**未爆的雷**:一旦有人日后把 runAdBuild/maybeAutoBuild import 进某个 client 组件,盐化 id 就会被下发、越权立即成真。修法零成本(去掉顶层 `"use server"`,与 v1 的 meta-write-actions.ts 完全对齐),**建议顺手修**,当 P3 加固处理。列在 P1 榜里是保留 run1 的最坏定级供你拍板。

### F22 · [Otto/Agent] — 原疑点已排除
**原 claim**:Otto stream route runs the agent AND finalizeOttoRun inside createUIMessageStream.execute — a client disconnect mid-stream aborts execution and the whole turn (user message + any tool writes) is lost / never persisted.

**为何排除**:Refuting guards: (1) the user message is written to the DB before the SSE stream opens, so no disconnect can lose it; (2) ai@6.0.208's createUIMessageStream never propagates consumer cancellation into execute — writes to a cancelled stream are silently swallowed by safeEnqueue and the execute promise keeps running on the Node event loop, so on client disconnect the agent run still drains, withLlmBudget still settles usage, and finalizeOttoRun still CAS-persists the assistant message + ottoState. The only effect of disconnecting is that the client misses the remaining live SSE frames; the completed turn appears on reload. The claimed "whole turn lost / never persisted" outcome is unreachable in the current code and deployment.
