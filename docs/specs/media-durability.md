# 媒体可恢复（最小层）规格书（S1）

> 状态: 草稿
> 批准: （冻结时填）https://github.com/BELCORT-SDN-BHD/FIKIRTIVE/issues/871 Founder 评论「S1 批准 media-durability.md」(YYYY-MM-DD)
> 规格前缀: MEDIA（验收编号 = MEDIA-A1、A2…，全仓不得与其他规格撞前缀）

## 0. 一句话

商家花钱生成的图、视频、配乐今天在云存储里只有一份，误删即永久灭失；这版做最小层——内容桶打开版本历史，加一份媒体恢复手册，并真跑一次「删掉一个已付费产物 → 按手册捞回来」的演练留证，商家因此在误删之后还捞得回自己花过钱的东西。

## 1. 九问（S1 grill 的答案）

1. **商家做什么动作、看到什么结果？**
   - 商家本人不做新动作，界面零变化。变的是事故之后的结局：商家 Aisha 删掉一条已付费的视频产物（或我们误删），今天她只能重新付费再生成一次；本规格落地后，操作者照手册在几分钟内把同一个对象捞回原键，她刷新页面产物还在，没有二次扣费。
   - 「商家做 X」在验收表里由操作者代演——这是加固类规格，演示对象是对象存储与手册，不是 UI。
2. **入口在哪里？（列全，含深链）**
   - Cloudflare 控制台：内容桶 `fikirtive-staging` / `fikirtive-production` 的 object versioning 开关与 lifecycle 规则。**Founder 亲手开，凭据不经 agent**（Founder 已裁 2026-09-12（#1359 场②））。
   - 新文件 `docs/runbooks/media-restore.md`（媒体恢复手册＋演练记录）。
   - 只读核验命令写进该手册；agent 用的是只给读权限的路径，不新增任何生产写入入口。
3. **四态：空、加载、错误、成功各长什么样？**（此处的「态」= 恢复演练的四态，无 UI）
   - 空：对象键在桶里连历史版本都没有 → 手册要求当场停手并升级到 Founder，不得自造替代对象。
   - 加载：恢复命令执行中，手册要求把命令与输出原样贴进演练记录。
   - 错误：版本列不出来、权限不足、键写错 → 手册给出三条对应处置，且一律 fail closed（宁可不恢复，不许覆盖现存对象）。
   - 成功：对象回到原键，字节哈希与原件一致，产物页面能重新打开。
4. **数据从哪来、写到哪去？**（证据以主干 `368e9094` 为准，2026-09-12 只读核证）
   - 媒体对象落在内容桶（`R2_BUCKET`，`packages/core/src/env-contract.ts:748`）；数据库备份走另一个隔离桶 `R2_BACKUP_*`（`env-contract.ts:818`），**不覆盖内容桶**。
   - 现状缺口：媒体侧零备份零复制——`packages/storage/src` 只有 `index.ts` 与两个 local-disk delete 测试，全仓 versioning/replication 仅一处注释命中 `apps/worker/src/db-backup.ts:238`（讲备份桶）。
   - 手册自己把这条列为未关缺口：`docs/runbooks/db-backup.md:205`「媒体(R2 内容对象)的备份策略仍是空白」；同文件 `:199` 的 versioning 待办只给备份桶。
   - 恢复演练脚本今天只有数据库版（`scripts/db-restore-drill.sh`）；`scripts/tools/r2-configure.mjs` 只设 CORS 与 multipart lifecycle（该文件 3-5、74-88 行），不碰 versioning。
   - 风险近期变大：commit `71fbe75e`「删演员真删资产与存储对象」把软删改成真删字节，判官意见（`1b8027ff`）明写「删字节不可逆」。
   - 本规格不改任何应用代码路径、不改 schema、不写数据库；产出物是两处桶配置 + 一份手册 + 一次演练记录。
5. **碰不碰钱路（credits / 计费）？碰则幂等键是什么？**
   - **碰，但只碰「已扣款产物的存续」，不新增任何扣款、退款或 ledger 写入**。恢复是按对象键放回字节，不重新生成、不再走 reserve/settle，因此没有新的幂等键。
   - 反过来说：产物灭失今天会变成退款或赔付争议（beta-gate GATE-A6 的钱路由来）。验收 MEDIA-A6 用账本快照证明「演练前后 `CreditLedger`（`packages/db/prisma/schema.prisma:912`）逐笔一致」——钱守恒是这版的硬判定。
   - 禁止用「重新生成一次」冒充恢复：那会真花供应商的钱，演练记录里出现新的生成 job 即判 MEDIA-A4 不通过。
6. **权限与租户边界是什么？**
   - 不改应用层授权代码，也不新增租户相关查询。边界落在操作规程上：恢复**只按单个对象键做**，禁止整桶回滚（整桶回滚会把别的租户对象一起改回旧状态）。手册须写死这条，并要求恢复前先核对该键的租户/org 前缀属于目标租户（MEDIA-A9）。
   - 凭据分工：Founder 在控制台开关与铸令牌；agent 与演练脚本只用最小权限的只读／演练桶令牌，永不读也不回显生产写令牌（沿用 `docs/runbooks/r2-bucket-token-rotation.md` 的口径与钥匙串做法）。
7. **参考对照：抄哪家？** 不适用：加固类规格，无 UI 参照。对照物是我们自己的数据库演练（#870 / `docs/runbooks/db-backup.md`）——同样的「手册＋一次真跑＋回填 RTO」形状。
8. **胃口：轻／中／重挡，为什么？**
   - 重挡：新建规格、演练脚本读写真实对象存储、且直接挡 GO（beta-gate `GATE-A6`，`docs/specs/beta-gate.md:79`）。#1290 已指定「重挡，需新规格」。
   - 胃口一天：控制台开关（Founder，分钟级）＋手册（半天）＋一次演练与留证（半天）。超出就砍 lifecycle 档位调优，保留「versioning 已开 + 演练跑通」两件。
9. **Otto 怎么协助这个功能？** 不适用（运维加固，商家面与 Otto 面都没有新动作）。

## 3. 不做（非目标；写明为什么和触发条件，防「遗漏」误会）

- **跨区／跨桶复制**：#871 后半已拆进延后台账 `docs/DEFERRED.md:103`（D-097），触发条件 = GA 前。本版只做单桶版本历史。
- **自动化的媒体备份任务／定时校验**：最小层靠桶自带的版本历史，不写新 worker、不建 cron。触发条件 = 出现第一次真实误删事故，或 D-097 启动。
- **数据库备份**：已有（`docs/runbooks/db-backup.md`），本规格只管媒体对象。
- **改商家可见 UI（回收站、版本历史入口）**：这是运维能力不是产品功能；要做须另开规格。
- **生产桶的删除演练**：零生产风险优先，生产桶只验开关状态（MEDIA-A7）。触发条件 = Founder 明确要求在生产真演。
- **成本核算表**：30 天保留的存储成本**未验证**，施工时以 Cloudflare 现价核一次并写进手册，不在本规格里编数字。

## 4. 异议栏（AI 必填）

- **最大风险：Cloudflare R2 是否真的提供 S3 式 object versioning，我无法从仓库证实——这条未验证。** 如果控制台没有这个开关，本规格的最小层（A1/A2）当场落空，而 A3–A9 全建在它之上。施工第一步应该是 Founder 打开控制台看一眼那个开关在不在（两分钟），而不是先写手册。备选口径（若开关不存在）：改用「删除即复制到隔离回收前缀 + lifecycle 过期」，那是另一种实现、需回 S1 重裁，不能由 agent 顺手改。
