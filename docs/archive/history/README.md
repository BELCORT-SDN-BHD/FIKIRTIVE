# docs/history — FIKIRTIVE 项目档案馆

> 性质:**证据层,不是权威层**。产品权威永远是 live `docs/BLUEPRINT.md`、durable Founder
> Resolution 与现行项目法;本目录记录「我们如何走到这里」,现状一律以 live 查询为准。
> 任何档案内容与权威层冲突时,以权威层为准并按流程对齐。

## 导读

**5 分钟版**(新协作者最快上手):
1. [FOUNDER-JOURNEY.md](FOUNDER-JOURNEY.md) 末尾的**产品词典**——先会说这座城的语言;
2. [DECISION-INDEX.md](DECISION-INDEX.md)——Founder 决策单行索引,每条链接到出处。

**完整版**(建议顺序):
1. [PROJECT-HISTORY.md](PROJECT-HISTORY.md) — 编年全史:每个时代做了什么、为何转向、出过什么事、哪条规则因此成法;
2. [FOUNDER-JOURNEY.md](FOUNDER-JOURNEY.md) — Founder 思想历程(原话逐字)+ 产品词典;
3. [BIG-PICTURE-MAP.md](BIG-PICTURE-MAP.md) — 大局观现状地图 + 偏差与升级清单(快照;见下方刷新约定);
4. [VISION-FUSION.md](VISION-FUSION.md) — 愿景融合与 Otto 最优化融合方案(快照;决策输入)。

## 快照与刷新约定

- 《PROJECT-HISTORY》《FOUNDER-JOURNEY》是**累积档**:只追加、不改写既有史实;新时代结束后追加新章。
- 《BIG-PICTURE-MAP》《VISION-FUSION》是**快照档**:卷首标注档案截点,过期即只作历史证据。
  刷新触发:每逢阶段闸门通过或时代审计完成后,以同一条流水线(提取舰队 → 综合 → Founder
  合并 docs PR)重放刷新;两次刷新之间,读者一律以卷首截点判断新鲜度。
- [DECISION-INDEX.md](DECISION-INDEX.md) 是**活索引**:每个工作 session 收尾时,当次 Founder
  新决策追加一行(史官仪式),经 docs PR 由 Founder 合并。

## 维护纪律

- 原话逐字,不翻译不润色;每句事实带出处;缺口如实标注,不补写。
- 本目录永不出现退役权威词汇(见 `scripts/check-project-authority.mjs`),CI 围栏强制。
