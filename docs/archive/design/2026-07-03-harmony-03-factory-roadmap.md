# Harmony 03 —— 广告工厂 MVP → 完全体路线图

> **性质**:harmony 交付物 3/6。兑现 founder 对工厂打法的条件批准:**"要很严格的执行那个步骤,不然我还是倾向于直接做到最棒的。"**
> 纪律 = 每个 MVP 占位件有**升级票 + 触发条件 + 不许超过的寿命**;这张表就是合同,总审查员按它验收。

## 一、工厂是什么(一句话)

**贴商品链接(或选 Product)→ 选人设 → 选拍法 → 出可投成片。** 卖的是"成品",不是工具箱。(C-01,对标 Higgsfield Marketing Studio,上线 30 天 68k 用户的品类。)

## 二、三波路线

### Wave 1 —— MVP(创作变现先锋,最快可收钱)
| 件 | MVP 形态 | 全量形态(升级票) |
|---|---|---|
| 冷启动 | **Product 档案 + URL 一键建档**(B-02;抓名称/图/描述) | + 多商品目录、Shopee/Lazada 链接解析 |
| 模式 | **3 个**:产品展示(Hyper-Motion 类)/ 开箱风 / 促销卡点 —— 全部无口播,现有 Seedance/Seedream 管线直出 | 10+ 模式(对标 Higgsfield) |
| 人设 | **多参考图一致性顶替**(现有 #92 能力) | PersonaIdentity 训练版(C-06) |
| 审美 | prompt skills 产品化成**风格卡片**(C-09,已有能力露出) | 预设库持续扩充 |
| 交付 | 成片 + Otto 配的文案,一键进排期/下载 | 整版成稿(C-11,以后) |
| Otto | **全流程可 Otto 驱动**(宪法 7:每步都是 skill,无人手断点) | + routine 化("每周一出 3 条") |

### Wave 2 —— 口播上线(转化率最高形态)
| 件 | 内容 | 前置 |
|---|---|---|
| Lipsync/TTS 供应商选型 | 硬性选型标准:①Otto 可全自动驱动 ②costing 过模型 ③多语(EN/BM/中) | costing 模型(harmony-04)+ founder 逐笔批验证花费 |
| UGC 口播模式 ×2 | 对镜头口播 / 测评风(Hook 模板前置 3 秒) | 供应商定 |
| 改台词不重拍 | 换促销词只重合成音画,不重生成 | 同上 |
| **升级票 U-1**:人设从"多参考图"换"训练版 PersonaIdentity" | 触发条件:工厂周产量 > 阈值(founder 定)或用户抱怨一致性 ≥ 信号线 | C-06 训练管线 |

### Wave 3 —— 完全体
| 件 | 内容 |
|---|---|
| Ad Reference 逆向工程(C-02) | 上传/由 Otto 从 ads library 找爆款 → 结构化拆解(**宪法 10:拆解 schema 化,弱模型可靠**)→ 套你的产品重拍;只拆结构永不复制素材 |
| 一稿多尺寸(C-03)+ 三语套装(C-04) | 工厂出片自动配齐全平台画幅 + EN/BM/中 |

| 效果反哺(O-10) | 投放数据 → 疲劳检测 → Otto 报告 → 批准后自动出下一轮(接 Campaign/分析区) |

## 三、升级票纪律(founder 的条件,写死)

1. 每张升级票在 backlog 里**建票即带触发条件**(时间/量/质量信号三选一),不许"有空再说"。
2. **MVP 占位件寿命上限一个 Wave**:Wave 2 上线时,Wave 1 的占位件必须已有排期或已升级 —— 否则总审查员在验收时打回。
3. 每个 Wave 出口 = founder 验收(runtime QA + 数字:出片成功率/成本/用户用量)。

## 给审查员的钉子
- [ ] Wave 1 全部件复用现有生成管线(不开新钱路);Wave 2 新供应商过 money-safety + founder 逐笔批
- [ ] 每步 = skill(Parity Manifest 登记),无人手断点
- [ ] C-02 拆解输出是结构 schema(hook/节奏/镜头序列/文案框架),禁止素材复制
- [ ] 升级票在任务系统可查,验收时逐票对
