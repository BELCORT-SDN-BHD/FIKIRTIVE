### 1.4 「本程内 / 本程外」边界表（本工位第一交付点 — 刀切线）

第一性张力（工单原文）：宪章明示 Shopee/Lazada **渠道**不在本程（`OUT-E415`）——但 B8 这五行是**内容优化 + 研究承接**（生成端），不是渠道 API 接入。下表把线画到刀切：

| 维度 | ✅ 本程内（B8 做） | ❌ 本程外（出 `OUT-E415`，越线即修宪章级） |
|---|---|---|
| **listing 内容** | 用品牌记忆+产品档案生成关键词/标题/属性/描述/主图文案草稿 | 把草稿经平台 API 写回 Shopee/Lazada listing |
| **交付动作** | 「复制到剪贴板」/ 结构化导出（CSV/字段块）供商家手工粘贴 | 自动上架、批量同步、库存/价格回写 |
| **店铺装修** | 生成 banner/分类页/促销楼层的**图文素材 + 文案** | 调用店铺装修 API 直接改店铺页面 |
| **竞价广告** | 生成关键词清单 + 出价**建议** + 广告文案素材（建议不代投） | 调 Shopee Ads / Lazada Sponsored Solutions API 真实创建/投放/调价 |
| **大促** | 官方大促**日历提醒** + 报名清单 + 备货/文案排产建议 | 代替商家在平台**报名**大促 / 提交官方券 |
| **直播挂车** | 生成开播预告物料 + 挂车商品文案（复用创作工厂） | 任何开播工具 / 直播间 API（`OUT-LIVE` 已排除开播工具） |
| **账号连接** | 无——本域不需要任何平台连接 | OAuth / embedded signup / token 存储（属渠道缝 seam 4） |
| **数据回流** | 商家**自报**效果 + 内部生成/导出计数（§6） | 从平台 API 读回排名/曝光/成交等平台侧指标 |

**边界一句话**：本程内 = 生成 / 优化建议 / 日历提醒 / 复制导出（**轻量流：生成→复制到平台**，人是最后一公里）；本程外 = 任何平台 API 写入 / OAuth / 自动上架（**渠道缝，规划新楼，非本程**）。

**两层性质澄清（供 founder 与审查判越线严重度）：**
1. **程序层**：越线 = 越出 Founder 已签署冻结的宪章 §二范围（`OUT-E415`），须通过对应 GitHub Founder Resolution 与适用的 Blueprint/计划修订流程，不是本工位或任何 agent 能自裁开工的。
2. **宪法层**：越线**本身不违蓝图宪法**——释宪附则⑦（v2.10，`BLUEPRINT.md:87`）已定：*FIKIRTIVE 自己作为消费方、经自家动作层与审批闸调用平台官方协议（含平台提供的 MCP）属渠道接入实现细节，不在「对外 MCP」禁区*。故将来渠道缝真开工时，Shopee/Lazada 官方 seller API 写入是**宪法允许**的，只是**本程不含**。两句必须分清：不越宪法，但越本程冻结范围。

## §4 六态 + 移动端

每个工作台面（尤以 ① listing 工作台）须显式设计六态：

| 态 | 触发 | 标准答案 |
|---|---|---|
| **empty** | 品牌记忆里无产品档案 | 引导先建产品（跳品牌记忆/创作工厂），不是空白页；文案「先让 Otto 认识你的产品」 |
| **loading** | Otto 生成中 | 骨架屏 + 进度；生成走既有 GenJob 异步，态与创作工厂一致 |
| **partial** | 部分字段生成成功、部分失败 | 成功字段可复制，失败字段单独重试（不整体重来，省 token——宪法 5 效率良心） |
| **success** | 全字段生成完成 | 逐字段复制 + 整体导出 + 「建议理由」可展开 |
| **failure** | 生成失败 | **标准答案（同模板）**：状态诚实——显示失败原因人话版、**自动退款已发生**（宪法 3 铁律③失败自动退款）、一键重试；绝不双扣 |
| **denied** | 权限/额度不足 | **标准答案（同模板）**：credits 不足 → 引导充值（money-in 走 Stripe，Otto 永不代办）；非本人/受限席位 → 说明所需权限，不静默失败 |

**移动端**：marketplace 商家高比例手机操作。listing 工作台移动端 = 单列纵向，字段卡可折叠，「复制」按钮拇指可达（底部固定）；导出在移动端降级为「复制全部字段块」（CSV 下载在移动端体验差）。日历移动端 = 列表视图优先，非网格。

### 6.1 listing 优化草稿：存哪？（两选一，附推荐）

### 6.2 大促日历数据源

### 6.3 效果衡量事件（喂 B2）

|---|---|---|---|
| `marketplace.listing.generated` | 生成一份 listing 优化 | `{ productId, platform, genJobId, fieldsCount }` | B2 计「优化了多少产品」 |

## §9 深度档位 A/B/C + 成本估算（含「A=只留缝」是否成立）

> B0-70 / B0-72 两行合同已注「体量过目裁深度」。下表给 founder 用 Q6 机制逐行裁量面。**核心问题（工单点名）：B0-70/72 的「A=只留缝」是否成立？**

### 9.1 B0-68 listing 优化（核心行，钱最重）

## §13 模板改进建议（v1.1 → v1.2 候选）

1. **建议模板增设「边界表」为固定节（§1.4 提升为独立小节标准件）**：本工位（及口碑、GBP 等「渠道相邻但内容承接」域）的第一交付点都是「本程内/外刀切线」。模板目前把它埋在 §1，建议对**渠道相邻域**明确要求独立「本程内/外边界表 + 两层性质澄清（程序层 vs 宪法层）」，避免每个相邻域工位各自发明格式。
2. **§9 深度档建议增设「A=只留缝 是否成立」标准判定栏**：本工单专门追问「A=只留缝是否成立」。建议模板对标「体量过目裁」行统一要求一个三判（成立/弱成立/不成立）+ 依据链，让 founder 一眼裁，而非每工位自由发挥。
3. **§6 数据契约建议强制「复用既有表 vs 新表」二选一表 + 推荐**：本域两次遇到（listing 草稿、日历种子）。模板可把「优先复用既有模型，新表需说明为何 `data` JSON 撑不住」立为默认纪律，呼应「简单优先 / 不为轻量流建整表」。
4. **§2 对标锚建议对「不接账号域」增设固定复核纪律注**：零原型 + 不接平台账号的域，对标只能查公开文档，容易失真。模板可要求这类域显式写「spec-ready 复核只查公开资料，不接真实商家账号」，防止后续设计人为对标去接账号（反而触碰边界）。
