## 二、缺失大陆排序（前 5 名）

**排序尺子（三因子相乘）**：① **离钱近**（这件事多直接给商家带来营收）× ② **城里全空**（我们现在有多空白，越空机会越干净）× ③ **原生机制有不公平优势**（我们的 research + Otto + 品牌记忆，能不能比龙头更省力地承接）。
三个都高的排前面。**打分是我的主观加权，透明列在诚实栏，founder 可自行重排。**

---

### 🥇 第 1 名：线下衔接 QR（"第一米"）

> 离钱近 = 高 ｜ 城里全空 = 高（缺整域，且是掉出候选表的孤儿项）｜ 原生优势 = 高（承接端已建好，补一小段就闭环）

**商家的第一性工作清单**
1. 生成"一扫/一点"就把路人变成线上可触达联系人的入口（QR + 短链，落点=进 WhatsApp/关注 IG/入群）——**本域所有后续动作的起点**。
2. 把入口输出成能真的印出来贴在桌上/收据角落/名片/传单/易拉宝上的实体图。
3. 知道贴在不同地方的入口各自带来多少新客（按位置做来源归因）。
4. 快闪摊位/市集现场把当场客流转成日后能再联系的名单。
5. 扫码进来的新联系人立刻收到欢迎语+被打上"来自哪个入口"的标签，直接接上现有对话与档案。

**龙头是谁**：respond.io Growth Widgets（QR + 多渠道 click-to-chat，$79 最低档就含）、ManyChat Growth Tools。

**我们原生机制怎么承接**：这是全图最不公平的一块——承接端已经建好了。收件箱、CRM 联系人档案、扫码后自动欢迎流程（M-04 Follow-to-DM 已批准）、来源打标签字段（harmony-01 首触来源）全在城里。缺的只是最前面那一米：一个能生成 QR+短链、由 Otto 用品牌记忆一键出可打印物料、并按贴放位置做来源归因的入口。龙头 respond.io 把这整套放进自己**最低价 $79 档**（说明它判定这是获客基本盘、不是高阶功能），我们仓库的竞品研究也判它"对大马门店/餐饮/服务业极高频、工程量小、演示效果好——性价比最高的一簇"。对我们是"补一小段就打通闭环"，不是从零起城。

### 🥈 第 2 名：口碑经济（评价 + 推荐 + 忠诚）

> 离钱近 = 中高（复购"第二笔钱"）｜ 城里全空 = 高（缺整域，referral/loyalty 两子域全线零落点）｜ 原生优势 = 高（零新平台 API，纯我们已有地基延伸）

**商家的第一性工作清单**
1. 成交后主动请顾客留评价（不干等）。
2. 多平台评价统一监控 + 差评预警（Google/FB/Shopee/Lazada 第一时间发现并回应）。
3. 把好评转成对外可展示的信任凭证（星级/证言）。
4. 设计"老客户带新客户"转介绍奖励，并追踪谁介绍了谁、发多少奖。
5. 会员积分/等级忠诚计划，让老客户为攒积分/升级持续回购。
6. 识别高价值/常客/VIP，针对性维系。
7. 衡量口碑/转介绍/忠诚的实际效果（带来多少新客、NPS、复购率）。

**龙头是谁**：Birdeye / Podium / Chatmeter（多渠道声誉管理）、Klaviyo Reviews、ReferralCandy / Talkable（转介绍）、Smile.io / LoyaltyLion、SEA 本地 Avocado Loyalty（忠诚）。

**我们原生机制怎么承接**：Otto + 品牌记忆天生就是评价回复引擎——用商家自己的语气起草差评公关/好评致谢，正中我们核心能力。转介绍和会员积分/等级是自动化+CRM 的活，而城里的自动化配方库（NS_RECIPES）、分群打标、broadcast+送达追踪、勿扰合规全部现成，接上"谁介绍了谁/积分累计"追踪就能跑。这是"复购/唤回"边界内理应覆盖却几乎空白的"第二笔钱"，**且不需要任何新平台 API**——纯粹是已有地基的自然延伸。现状：城里 65 个原型页 + 候选表全域关键词零命中，只有一条被主动砍窄的"请评+AI 回评"窄候选（还是"曾判不要-成本性"待复核状态）。

### 🥉 第 3 名：Marketplace 站内优化（Shopee / Lazada / TikTok Shop）

> 离钱近 = 高（多数 SEA SMB 唯一线上门面）｜ 城里全空 = 高（缺整域，6 件里 4 件完全缺失）｜ 原生优势 = 中（内容优化正中下怀，但推回平台有 API 门槛）

**商家的第一性工作清单**
1. listing 关键词/标题/属性/图片优化，让站内搜索算法把商品排前面。
2. 店铺主页与分类页装修（banner/导航/促销楼层）。
3. 站内竞价广告（关键词广告/推荐位）。
4. 商品评价与评分经营（催评+差评应对，评分是排名因子）。
5. 报名/蹭官方大促（11.11/Payday/官方券/flash sale）——免费流量分配最大杠杆之一。
6. 站内直播/短视频挂车（Shopee Live/TikTok Shop Live）。

**龙头是谁**：各平台 Seller Centre listing 质量分工具、区域第三方（BigSeller/Easy Data 等）、Shopee Ads / Lazada Sponsored Solutions、官方 Campaign Center。

**我们原生机制怎么承接**：listing 关键词/标题/属性优化本质是内容生成，正中 Otto + 品牌记忆下怀；官方大促日历（11.11/Payday）是 Otto 研究库（campaign/trends）的活；差评应对复用第 2 名那套。唯一门槛是把优化结果推回 Shopee/Lazada——但即便先做"在 FIKIRTIVE 里生成、复制到平台"的轻量流，也能立刻交付价值，不必等深度 API。考虑到这是 151 万 SEA SMB 唯一的线上门面、承接的是获客漏斗最前端（排不进前几页=对绝大多数客户隐形），钱的分量在全图最重。**诚实标注：平台 API 接入是这块的真实工程风险，原生优势因此打了折，排第 3 而非更前。**

### 第 4 名：Landing / link-in-bio 微站

> 离钱近 = 中（官网替代品）｜ 城里全空 = 高（缺整域，5 件工作全在"候选"档、零建造）｜ 原生优势 = 高（可能是全图最高，工程量小）

**商家的第一性工作清单**
1. 把"我是谁/卖什么/怎么联系"钉进 IG/TikTok bio 唯一那条链接里，当没官网时的替代官网。
2. 把这条链接做成能直接完成动作的迷你落地页（菜单/商品按钮/WhatsApp 一键开聊/预约）。
3. 为一次性活动/促销单独做收线索的落地页+表单，不为此建整站。
4. 知道这条链接/落地页有没有人点、从哪个渠道来。
5. 页面随生意变化**自动跟着更新**（新品上架/换季自动换文案）。

**龙头是谁**：Linktree（Start Page 免费档）/ Beacons / Metricool SmartLinks、GoHighLevel Funnel Builder。

**我们原生机制怎么承接**：这块的不公平优势可能是全图最高——候选表原文就写着"Otto 可按品牌记忆自动生成/更新（新品上架自动挂上）"。Linktree/Beacons 做的是**静态页**，而我们能做"随生意变化自动跟着更新"的**活页**：品牌记忆驱动视觉、创作工厂产内容、Otto 自动换季换文案。对没有官网的 85% 马来西亚 SME，这一条 bio 链接就是官网替代品。工程量小（独立轻量页+按钮列表+点击统计），是纯 content-gen play。现状：候选表两条相关行都标"存疑待 founder，从未进过 GRILL 拍板"，城里零页面/零 spec/零判决——但也从没被原则性排除过（不像"白标""对外 MCP"有宪法明文禁止），纯粹从未提上台面。

### 第 5 名：私域消息 WhatsApp Status（+ Telegram 频道广播）

> 离钱近 = 高（WhatsApp 命脉级）｜ 城里全空 = 中（主链已很扎实，缺口窄）｜ 原生优势 = 高（复用已接的 WABA，几乎零新工程）

**商家的第一性工作清单（本面缺口部分）**
1. 用 WhatsApp Status（24 小时朋友圈式动态）发新品/限时优惠/幕后——白嫖一个免费高曝光位触达已加好友的老客户。
2. 经营 WhatsApp 群组/Telegram 频道做订阅式广播，把私域流量沉淀成能反复触达的资产。
（本面主链——统一收件箱/分群/群发+重发+送达/冷启动导入/勿扰合规——**城里已有真实交互原型**，不在缺口内。）

**龙头是谁**：WhatsApp 原生 Status（Meta 自身）/ Statusbrew、Telegram Channel Broadcast / WhatsApp Community。

**我们原生机制怎么承接**：窄但高杠杆、且几乎零新工程。我们已经接了 WhatsApp（WABA），broadcast/送达追踪/勿扰全部现成，创作工厂本来就在产内容——Status 就是把已有内容多推一个免费高曝光位，Otto 用品牌记忆自动排期发闪购/新品/幕后。在命脉级渠道（WhatsApp 90.7% 马来西亚网民）上白嫖一个曝光位。**诚实标注：私域消息主链城里已经很扎实，所以这是"在已建域上补一块"而非开新域，"城里全空"这一项打了折——它排第 5 而非更前，正因为这一项弱。另 Telegram 是被代码类型层面（kit.tsx NsInboxChannel 三值枚举）显式排除，补它要先动渠道枚举。**

**紧随其后的第 6～8 名（供 founder 若要扩到前 8 时参考）**：
- **搜索与地图 GBP**（缺整域、离钱中、原生中）——GBP 对商家免费、买意流量真实，Otto 可承接发帖/回评/照片文案；但需 Google Business Profile API 接入（工程量≈Marketplace），且蓝图 L494 曾判"搜索可见度对 ICP 无用"，有政策张力，见诚实栏。

- **Google 搜索广告**（缺关键工作、离钱中、原生中）——被点名的第二梯队渠道，但 SEA 商家整体在从搜索转社媒，且 Google Ads 关键词结构与我们现有 Meta 广告模型不同。

## 三、诚实栏（证据强弱 / 判决两可 / AEO 翻案考据）

### 3.1 证据薄弱的面（不要因为写得笃定就当硬数据）

- **AEO（第 2 面）**：最薄。大盘趋势有真数据（马来西亚 AI 助手用量在涨），但"消费者用 AI 问答直接选一家本地小店"这个具体场景，搜到的几乎全是 AEO 代理机构自家营销博客（自卖自夸），没有一条独立第三方硬统计。目前是新兴/前瞻，不是已验证刚需。
- **Landing/link-in-bio（第 9 面）**：政府一手数据偏旧（DOSM 2019 年 web 存在感 53.9%、SME 年报 2016/2017 的 85.4% 靠社媒），没有一条专门量化"SEA 中小商家 link-in-bio 采用率"的调查，是"政府旧数据+行业侧面增长信号"拼出来的合理推断。
- **口碑经济-忠诚子域（第 8 面）**：评价子域证据较扎实（81–88% 看评价 + 马来西亚假评价敲诈真实案例）；但忠诚计划证据主要来自厂商博客/市场报告（Loyalty & Reward Co、Brierley 等有商业动机），缺"马来西亚多少% 中小商家实际在跑忠诚计划"的硬渗透率数据。
- **搜索与地图 GBP（第 1 面）**：GBP 采纳率 35%、评价信任 83%、near me 46%、本地搜索到店 80% 这几条硬数据都是**全球/欧美口径，非马来西亚专项**；唯一 SEA 口径的数字（约 40% 靠 Google 做发现，落后电商 57%/社媒 50%）说明它是真实但**非第一位**的入口。缺"马来西亚 GBP 渗透率"硬数字。
- **线下 QR-引流私域子用法（第 10 面）**：扫码支付月活 66.1%、WhatsApp 渗透 84% 是硬数据，但那是"扫码支付"和"WhatsApp 渗透"两条，不是"扫码进营销私域（关注/入群/留号）"这个更窄用法的直接证据——这层是常识推理叠加，明说没有专门硬数据。
- **Google 广告（第 5 面）**：没有"马来西亚小商家在 Meta/TikTok/Google 之间实际花费占比"的一手硬数据，用的是相邻可查证据（大盘规模 + 一份行业博客的定性渠道排序 + 渠道选择趋势的百分比变化），是严谨推理而非精确统计。
- **Email/SMS（第 7 面）**：没有马来西亚官方 SMB email/SMS 采用率硬数据；搜到的"每花 RM1 赚 RM36""82% 每天查邮件"多是营销代理博客把全球通用 ROI 数字包装成"马来西亚数据"，高度可疑，不采信为本地硬证据。

**证据扎实的面（可放心引用）**：Marketplace（Shopee GMV 份额、NESR 151 万 SME——硬）、社媒直播（TikTok Shop RM120.7 亿、九成卖家靠直播——多源交叉）、私域 WhatsApp（90.7% 渗透、IM 80% 份额——硬）。

### 3.2 判决两可的面（同一份证据可以读出两种结论）

- **私域消息 / Email/SMS / 社媒自然流量**：都判"缺关键工作"，但主链其实做得相当扎实——"缺"是窄口子（Status、email 渠道、直播），换个角度也能读成"基本覆盖、只差补边"。判决取"缺"，是因为按信道字面意思核对，页面存在≠那件工作做完。
- **搜索与地图 GBP**：判"缺整域"，但蓝图 WHATPASS L494 实质上把"搜索可见度"判成"对 ICP 无用"（理由：SEA 主战场在社媒/WhatsApp）——所以这到底是"漏掉的缺"，还是"有意识地让给别人、主动 cede"？两可。调查员的诚实结论是：从 2026-07-03 定调起这整个面就没被圈进"对标全量"，不是漏扫，是从未圈进来。
- **Email-SMS 部分**：SMS 判"完全缺失"，但这是排除清单里两次记录在案的**审慎排除**（东南亚运营商不支持 Klaviyo/ManyChat 式批量 SMS + WhatsApp 已替代同等价值），founder 已有理由存档——是"排除对了"，不是"漏了"。
- **AEO**：3/5 件工作判"城里已有"，但全部挤在同一张页面、且页面自己标注"Sample run / 写死 mock、未接真引擎"——"存在页面"≠"覆盖工作"，别因页面存在就判"基本覆盖"。

### 3.3 AEO 翻案考据（治理记录矛盾——最需要 founder 拍板的一处）
