## Problem Statement

Founder 早已批准了北极星(沉浸式)设计——这就是他要的产品样子。但工程上它停在预览开关后从未转正;同时线上另有一块朴素画布在持续吃修复。结果:**批准过的设计被搁置,维护的却是不想要的样子,而且两套实现让每个画布修复都要做两遍。** 更深一层,画布的底层数据(谁生了谁、这是第几张、做完了没有)靠猜而不靠事实,导致假血缘、A/B 标签漂移、永久转圈等病反复冒头。

## Solution

**皮用北极星,芯用修好的那套,合成唯一一块画布;底层事实全部落盘,不再猜。** 北极星的视觉与交互(嵌入式 Otto、血缘树、A/B 对比、credits 常显)成为产品唯一画布的样子;内核沿用成熟画布引擎(@xyflow 系)与两轮判官修真过的数据层;逐页替换、Founder 验一页收一页;全部转正后预览开关与手搓引擎退役,「两套画布」从词汇表删除。

## User Stories

1. As a 商家, I want 打开产品只看到一块画布——就是 Founder 批准的北极星样子, so that 我用的产品和设计愿景一致。
2. As a 商家, I want 一次生成的 4 张图显示为「同一批的 4 个兄弟」(带 1/4 组框), so that 我不会被虚构的「母图生子图」故事误导。
3. As a 商家, I want 点开任何一张图的 Info 立刻看到真实血缘(从哪张来、哪个任务、花了几积分), so that 每个东西都有迹可循。
4. As a 商家, I want 生成完成的瞬间卡片就变完成、谱系就位, so that 我不用刷新或干等。
5. As a 商家, I want 关掉页面再回来时,已付费的产出一张不少地出现在画布上, so that 我的钱不会买到会消失的东西。
6. As a 商家, I want 点一下卡片只是选中它、把它交给 Otto 是一个明确的独立动作, so that 我可以放心浏览而不触发副作用。
7. As a 商家, I want A/B 对比标签永远指向真正的 A 和 B(不因拖动换位而互换), so that 我截图给同事时说的 A 就是 A。
8. As a 商家, I want 失败/降级/过期的卡片显示确定的终态而不是永远转圈, so that 我知道该重试还是该放弃。
9. As a 商家, I want 排队中的任务如实显示「排队中」, so that 我不被「正在制作」误导。
10. As a 商家, I want 从某张图衍生的新结果落在那张图旁边并连线, so that 画布的空间关系反映创作关系。
11. As a 商家, I want 刷新或他人任务完成时我已选中的卡片保持选中, so that 批量操作不被打断。
12. As a 商家, I want 画布上显示我的 credits 余额与每次生成的花费, so that 花钱前后心里有数。
13. As Otto, I want 读到的画布谱系与事实一致, so that 我的编排建议不建立在假关系上。
14. As Founder, I want 每一页北极星转正都有真实界面走查截图作为验收证据, so that 「合并了」等于「我看过且认了」。
15. As Founder, I want 旧画布在新页通过我验收前保持可用可回退, so that 转正过程零风险。
16. As a 复审判官, I want 状态与谱系有单一权威推导函数和有限状态集, so that 复审有明确不变量可核。
17. As a 后续开发者, I want 只有一份画布实现, so that 每个修复只做一次、验一次。

## Implementation Decisions

- **D1 引擎裁决(Founder 2026-08-01)**:唯一画布引擎 = 现役成熟画布库内核(FlowCanvas 系);北极星手搓拖缩引擎退役。北极星的视觉规格(布局、token、嵌入式 Otto、credits 常显)为唯一外观权威。
- **D2 装配方式**:北极星 create/canvas 页的受控入口(现有 fenced Entry seam)改挂修真后的画布内核;不在手搓板上修数据,不在旧外观上补视觉。
- **D3 服务端结算(体检 Q8=A)**:「把做好的卡片写上画布」成为生成任务完成路径的最后一步(后台一次写定整批),读路径转纯读;现存多套读时对账逻辑随之删除。此项触碰 worker 完成路径,按钱路邻接对待,复审重点=不改 spent/committed 语义。
- **D4 状态代数落库**:画布卡状态收敛为有限互斥单向集(排队→进行中→成功|失败|已取消),数据库加取值检查(本仓其他六张状态表已有同款);兜底分支一律「未知」不得为「生成中」。**涉及 migration → Founder-only 合并。**
- **D5 批次身份落盘(体检 Q4=A)**:批内序号与批大小写入产出行(服务端已有该事实);A/B 标签、组框、批次折叠一律读落盘事实,坐标只管摆放永不定义身份。布局锚点与生成来源分列两个字段(#597 已起步的 madeFromSource 为准)。
- **D6 点击语义(体检 Q5=C)**:点=选中;「送去 Otto」为工具条上的显式动作;无会话时点击不产生错误提示。
- **D7 逐页转正与退役**:每页一票、附真实走查截图、Founder 验收;全部页通过后删除预览开关、下线手搓引擎与重复实现;届时删除 northstar 相关死分支。
- **D8 视觉搬运顺序**:先 canvas 页(本 spec 主体),血缘树与 A/B 对比 UI 在 D5 数据修真后搬运;其余六页壳按同法后续逐页(各自出票,不在本 spec)。

## Testing Decisions

- 只测外部行为:组件级测试驱动真 FlowCanvas + 真节点组件 + 真谱系面板(先例:#597 r2 的 canvas-flow-lineage-ui.test.ts);断言商家可见结果(锚、组框、标签、终态静止),不断言内部函数调用。
- 状态代数与谱系推导各有单一纯函数,穷举态测试(先例:#595 r2 的 otto-status-helpers 测试)。
- 服务端结算用真库集成测试:任务完成→整批卡片一次落定;浏览器全程关闭的场景必须绿(先例:两个板读取器的失败注入测试)。
- 每项修复交付前:未修实现上先红(mutation 或场景红证),原始输出存档可查。
- 每页转正附浏览器真实走查截图(dev server + 授权账号),作为 PR 验收证据。

## Out of Scope

- 竖版/画幅能力(独立核心功能 spec,钱路类,另呈)。
- 参考语义统一(体检 Q6/Q7/Q11/Q12:@ 引用到底改不改真图、「再来一张」语义、元素基准形象、截断提示)——下一个 spec 专门处理,避免本 spec 膨胀。
- 规格展示与可改性(Q9)、声音开关处置(Q10)、老图溯源回填(Q13)——各自小票另行呈批。
- 节点连线式工作流、无限滚动生成、创作事件账本、多档视频模型(体检「明确不做」清单,防完美漩涡)。
