### 0.2 GBP 张力结论链（学 OUT-AEO 考据格式；本节为本文件最载重的一段）

**争点**：MISSING-CONTINENTS 诚实栏点名——蓝图/WHATPASS「L494」曾判「搜索可见度对 ICP 无用」，与宪章 §三 B8「GBP 归并行泳道薄试」正面冲突。B0-75 到底受不受 L494 约束？

**第一步 · 原判到底排除了什么（读原文，别读转述）**
- `docs/northstar/WHATPASS-V2-CANDIDATES.md` **第 494 行**原文排除项 = 「HubSpot **AEO**（Answer Engine Optimization，追踪品牌在 ChatGPT/Gemini 等答案引擎中的可见度）**add-on**」；判词 =「对 ICP 明显无用——**依赖客户有内容型网站 + SEO 战略**；SEA SMB 主战场在社媒/WhatsApp，不在搜索/AEO」。
- `docs/research/GRILL-WORKSHEET-2026-07-03.md` L782 佐证同一批排除：「SEO / AEO 工具（HubSpot topic clusters、Google Search Console 集成、AEO add-on $50/月）— 刻意排除：**依赖客户有内容型网站**，SEA SMB 主战场在社媒；**属内容/网站域**，不属社媒分析域。」
- **关键读解**：L494 的排除**对象**是「AEO/SEO 内容网站可见度工具」，其排除**前提**是「**依赖客户自有内容型网站 + SEO 战略**」。它排除的不是「Google 这个渠道」，而是「一套需要客户先有 SEO 网站才成立的付费追踪 add-on」。

**第二步 · GBP 是不是同一物（前提检验，OUT-AEO 手法）**
- GBP（Google Business Profile）= **免费商家档案认领 + 发帖 + 回评 + 照片文案**。它**不依赖客户自有内容型网站**——档案本身就是 Google 免费托管的商家页，near-me 搜索/地图买意流量直接落在档案上。
- 因此 L494 的排除**前提（依赖内容型网站）对 GBP 不成立**。这正是 OUT-AEO 考据的检验动作：「原判前提是否仍成立？」——AEO 面前提仍成立（aeo 页六维评分仍含 Structured content / Content depth，仍需内容网站，故 OUT-AEO 留 `OUT-deferred`）；**GBP 前提不成立，故 GBP 与 AEO 分道**，不被 L494 覆盖。

**第三步 · 现行法是什么（哪个是现行法 + 为什么）**
- **锚一（宪法层）**：蓝图 **L47** 边界表「本体负责」列**明文含「本地发现（搜索&地图）」**。GBP = 本地发现，**宪法正面纳入本体负责域**。这是最高阶依据（宪法 > 判决 > 舱单）。
- **锚二（总计划层）**：`docs/ops/ROUTE-B-MASTER-PLAN-2026-07-12.md` §三 B8 明文「**GBP 归并行泳道薄试**」——已冻结（founder 五答签认，2026-07-12）。
- **改判留痕（治理卫生）**：GBP 薄试的 current 依据是 Blueprint「本地发现」边界与 aligned Route-B B8；旧逐行 adjudication 由 Git 历史保存，不再作为 active authority。若两层 current authority 冲突，停下交 Founder，不从旧审计包恢复结论。

**结论链（一句话）**：
> **现行法 = GBP 薄试在本程**（Blueprint 本体负责边界 + aligned Route-B B8 双锚）。L494 排除的是「依赖客户自有内容型网站的 AEO/SEO add-on」，其排除前提对 GBP 不成立，故不约束 B0-75。AEO 面继续 `OUT-deferred`，与 GBP 分道；B0-75 只按「薄试」形态设计，不做需内容网站的 AEO 套件。

**遗留提请（非本工位裁）**：MISSING-CONTINENTS §3.3 的 AEO 未记录翻案考据（R-003）仍未决，与本 GBP 结论**互不牵连**——GBP 的改判不代表 AEO 也应改判（前提不同）。此点入 §12 开放问题。

### 0.5.2 GBP 两层性质澄清（Q4 细化对齐）

GBP 是五行里唯一碰第三方平台 API 的行，必须拆三层，各层花费/审批闸不同：

| GBP 子动作 | 性质分层 | 时点（Q4 细化） | 花费/审批闸 |
|---|---|---|---|
| **GBP API 接入申请**（Google 审 app、拿 API 配额） | **材料类前置**（长周期身份验证，非产品递审） | 施工期办、**受审面就绪就递**（Q4 细化：不等全城收口） | $0；递审窗口一批递（与 Meta/Cloud API 同批，见 Master Plan §八 Q4） |
| **GBP 读**（档案信息、评价列表读取） | 连接授权回执（inbound OAuth；宪法 §四附则⑤「收信与授权回执，不是给外人钥匙」） | 商家自助连（GRILL L242 连接器自助化） | **$0 读**；`reach=internal`（只读回我们库），公式 needsApproval=false |
| **GBP 写**（发帖、回评、上传照片文案） | 经 GBP API **写第三方平台** | 薄试范围内（Otto 起草→人批→发） | `effect=write ∧ reach=external` → 公式 **needsApproval=true**，逐条人批 |

> **两层澄清收口**：「GBP API 申请 = 材料类前置（施工期办）」为工单已明示；「GBP 写入 = ？」的答案 = **`reach=external` 写动作，走审批闸**（不是材料层，是运行期动作层）。QR/微站/落地页/增长实验四行**零平台 API**，无此分层——如实列为「无渠道相邻域两层性质」。

## §4 六态 + 移动端（顾客侧公开面加「无登录态」维）

> 六级状态迁移规则见 `../B0-CONTRACT.md` §一。本节列每行的 UI 六态；**扫码/点击/填表端 = 顾客侧公开面**，故在标准六态外加一维「**无登录态**」。

### 4.1 商家侧（owner 面）六态通则

| 态 | 通则（五行共用） |
|---|---|
| happy | 物料/微站/GBP 帖生成成功，coral 高亮 Otto 动作 + 简短叙述（宪法 11 原则③） |
| empty | 「还没有物料/微站/连接」空态 = **Otto 一键起步 CTA**（宪法 11 三查①），不是死空白 |
| loading | 生成中骨架屏；渲染 QR PNG / 微站预览异步（Seam 6），不阻塞 |
| **denied** | **`requireOwner` + 不泄露存在性**：非 owner 访问返回中性 404（不是 403，no existence oracle，对齐 L0 spec §四.4 `keyOwnerMatches`） |
| **failure** | **局部降级 + 显式重试**：如物料某一版式渲染失败，其余版式照出，失败版式给「重试这一张」按钮；GBP 写失败给「重试发帖」，不整页崩 |
| retry | 幂等重试（生成 $0 可安全重放；GBP 写经 idempotencyKey 防双发） |

### 4.2 顾客侧公开面（无登录态维）—— B0-62 扫码端 / B0-73 微站 / B0-74 落地页

| 态 | 顾客侧行为（无登录态） |
|---|---|
| **无登录态** | 扫码/点链/看微站的人**永远匿名**，无账号、无登录墙。事件 scope 到 `link.ownerId`（server 侧解析，**永不信客户端传 owner**，L0 spec §四.4）。 |
| happy（顾客） | 扫码→重定向到目的地（WhatsApp/微站/GBP 评价页）；微站→按钮可点一键开聊；落地页→表单可填 |
| **吊销态**（顾客） | 码/链接被吊销 → **商家品牌中间页（HTTP 200）**，不是死 404；「此码已失效，试试这里」+ 安全下一步（L0 spec §四.3）。**已吊销与从不存在返回同一中性页**（no existence oracle） |
| failure（顾客） | 微站某 block 加载失败→局部占位，其余照显；表单提交失败→保留已填内容 + 显式重试，不丢数据 |

### 4.3 移动端

- 顾客侧公开面 = **移动优先**（扫码 66.1% 月活场景本就在手机；WhatsApp 主渠道）。微站/落地页单列、拇指可达、按钮大靶区。
- 商家侧生成物料/管微站可桌面为主，但预览须移动端所见即所得（顾客看到的就是手机版）。

## §7 权限/花费闸逐行初判

> 审批数学（宪法 7 / L0 spec §九）：`needsApproval = (cost=spend) ∥ (effect=write ∧ reach=external)`；信任是格子不是梯子——公式之上按「动作类别 × 波及面 × 可逆性」**只加严、永不放松**（安全 > 效率）。

| 行 · 动作 | cost | effect | reach | 公式 | 格子加严 | 结论 |
|---|---|---|---|---|---|---|
| B0-62 生成物料/QR/短链 | free（$0，同 L0，不扣 credits） | write | internal | **false** | — | **Otto 可代办，无审批**（生成即 $0，见 §6.1；不走记账缝 Seam 3） |
| B0-62 吊销**有 PRINTED/DEPLOYED placement** 的物料 | free | write | internal | false | **加严→人批** | 物理召回不可逆（撤印在 N 张贴纸的码），**人批**（复用 L0 召回流程 + 可选 MEASUREMENT_CARD） |
| B0-73 发布/更新微站 | free（自有托管） | write | internal | false | **加严→人批** | 微站是**对外可见公开面**：内容变更（尤其 Otto 自动换季）**须人批**——虽 reach 技术上 internal（我们自己的库），但顾客可见，格子加严为人批（对齐宪法 11 信任阶梯） |
| B0-74 发布落地页 / 收线索 | free | write | internal | false | 同微站→人批发布 | 发布人批；线索**进来**（顾客填表）=自动记 SourceTag（$0，无审批） |
| **B0-75 GBP 读**（档案/评价） | free | read | internal | false | — | Otto 读对等 skill，无审批 |
| **B0-75 GBP 写**（发帖/回评/照片） | free（不扣 credits） | write | **external** | **true** | — | **逐条人批**（写第三方平台，公式直接 true；Otto 起草→人点批→发） |
| B0-76 读实验净值 | free | read | internal | false | — | Otto 读对等，无审批 |

**花费闸专述**：
- **五行的「生成」全部 $0**（物料/QR/短链/微站/落地页生成都是确定性动作，像 L0 `schedulePosts` 只建 DRAFT）——**不走记账缝 Seam 3，不扣 FIKIRTIVE credits**。任何把这些接进 credit ledger 都是错的（L0 spec §五）。
- **微站托管成本 = 平台侧（标出）**：自有托管页的服务器/CDN/存储是**我们的基础设施成本**，不是用户 credits，走 B10 成本监控（BytePlus 余量告警同类），**非用户可见花费闸**。若微站量大需独立 costing，喂 B9/B10（不在本设计裁）。
- **GBP API = $0 读写分层**：GBP 官方 API 读写对商家免费；我们不因 GBP 写扣 credits。但**GBP 写=审批闸（非花费闸）**——闸的是「写第三方」的 reach，不是钱。
