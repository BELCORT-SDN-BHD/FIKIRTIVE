## 1. TOP REDUNDANCIES / DUPLICATES (ranked by impact)

### R1 — `COWORK_PAID_PROVIDERS_ALLOWED` is a redundant double-lock over `COWORK_PROVIDER` ★ #1 concern
- **Where:** `apps/web/lib/runtime-config.ts:38-42` (reads both env vars) → `packages/core/src/runtime-config.ts:43-51` (`effectiveCoworkProvider` forces `undefined`→Mock when `!paidAllowed`).
- **Why redundant:** `createTransportFromConfig` (`packages/core/src/runtime-config.ts:54+`) **already** throws if `provider==='fal'` without `FAL_KEY`. So three gates guard one decision: (a) `COWORK_PROVIDER` enum, (b) `COWORK_PAID_PROVIDERS_ALLOWED` boolean, (c) credential presence. Cited by 5 of 6 dimensions as the headline.
- **Consolidate (recommended):** Delete `COWORK_PAID_PROVIDERS_ALLOWED` and the `paidAllowed` param. Make `COWORK_PROVIDER` unset/`mock` the safe default; a paid value only activates when its credential is present (already enforced by the throw→catch→Mock fallback at `getTransport`). One env var = one source of truth.
- **Caveat before deleting:** `COWORK_PAID_PROVIDERS_ALLOWED` is the documented closed-beta kill-switch (`docs/closed-beta-env-checklist.md`). Keep ONE explicit lock, but it should be the *only* one. Either keep `COWORK_PROVIDER` (and drop the boolean) or keep a single `COWORK_PAID_ALLOWED` boolean and drop the enum — not both. Update `cowork-transport.test.ts` + `runtime-config.test.ts`.

### R2 — Vision config sprawls across 3 env vars
- **Where:** `packages/core/src/cowork.ts` `coworkVisionConfig()` reads `COWORK_VISION_ENABLED` / `COWORK_VISION_MAX_IMAGES` / `COWORK_VISION_MAX_BYTES`; merged in `mergeVisionConfig` (`packages/core/src/runtime-config.ts:29-37`) + `resolveVisionConfig` (`apps/web/lib/runtime-config.ts:24-28`).
- **Consolidate:** DB `RuntimeConfig` row (`vision` key) already exists and overrides env — the 3 env vars are now only the emergency baseline. Keep `COWORK_VISION_ENABLED` as the sole hard kill-switch; move the two caps to the DB row only (admin SettingsAdmin already writes vision). Document, don't multiply.

### R3 — Auth allowlist split: `FOUNDER_ADMIN_EMAILS` + `AUTH_ALLOWED_EMAILS`
- **Where:** `apps/web/auth.ts:45`, `apps/web/lib/allowlist.ts:13-14` (both checked in `isAllowedEmail`).
- **Consolidate:** Keep both (distinct roles: super-admin seed vs outer gate) but rename `FOUNDER_ADMIN_EMAILS`→`SUPER_ADMIN_EMAILS`, document that super-admins must also be in `AUTH_ALLOWED_EMAILS`. Lower priority — this is naming, not true duplication.

### R4 — DB connection naming inverts semantics
- **Where:** `packages/db/src/index.ts:20` (`DATABASE_URL_POOLED || DATABASE_URL`), `:28` (`DB_POOL_MAX`).
- **Consolidate:** Naming/doc only. `.env.example` should state: runtime uses pooled, Prisma migrate uses direct. Don't rename the var (Railway/Neon convention) — just document.

**Net:** R1 is the only true redundancy worth code change now. R2 is a simplification. R3/R4 are naming+docs.

- **Real gaps to document (not bugs):**

## 4. OTTO IMAGE-VS-VIDEO BUG (#3) — root cause + fix

**Root cause:** The DTO silently coerces a missing `kind` to `"image"`.
- `apps/web/lib/dto.ts:65` — `kind: p.kind ?? "image"`.
- The worker **always** writes a concrete kind: `apps/worker/src/jobs/gen.ts:118` — `kind: job.kind === "VIDEO" ? "video" : "image"`. `GenJob.kind` itself is always set (`gen-actions.ts:94,113`). So a missing `p.kind` at the DTO means payload corruption/schema drift — and the `?? "image"` masks it, rendering a video result as an image card.

**Precise fix (dto.ts:65):**
```ts
// was: kind: p.kind ?? "image",
kind: p.kind === "video" || p.kind === "image" ? p.kind : (() => {
  console.warn(`GEN_RESULT payload missing/invalid kind for genJobId=${m.genJobId}`);
  return "image"; // last-resort, but now observable
})(),
```
Minimal version: keep the fallback but add the `console.warn` so corruption surfaces. Stricter version (preferred if no legacy rows): drop the fallback, log, and skip rendering the card.

**Secondary (test-coverage gap, not the bug):** `mockPlannerReply` (`packages/core/src/cowork-planner.ts:87`) hardcodes `kind:"image"`, so dev/test never exercises a planner-initiated *video* proposal. Make it return `kind:"video"` when `userText` matches `/video|animate|motion|clip/i`. This is why the bug wasn't caught locally.

**Tertiary:** planner system prompt (`cowork-planner.ts:13`) gives one sentence on video. Add explicit image-vs-video selection rules.
