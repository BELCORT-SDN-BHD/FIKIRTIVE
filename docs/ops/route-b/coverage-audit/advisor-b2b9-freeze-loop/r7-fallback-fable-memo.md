# 备忘录：③④⑤ 修复方向裁定（R7 BLOCK → v1.0/R8）

## 结论先行

**③④ 采选项 A（换轴到达序 + per-review 单锁单折叠），⑤ 采选项 B 加固版（XID-先于-nextval 协议，但必须收进单写者函数并补冻 CACHE=1）。选项 C 驳回。**

关键依据不是偏好，是两条硬事实：

1. **选项 B 对 ③ 根本不可实现**。「离线重建模拟在线门」要求重放时知道每笔观测**到达时刻的行态**，而行态由到达序决定。现有真源里没有任何可用的到达序载体：`createdAt @default(now())`=事务开始时刻（并发下与提交序可互换），ULID `id` 在应用层、取锁前铸造（同样可倒序）。没有耐久到达轴，「模拟在线门」就是重放不出来的；补上到达轴，B 就变成了 A——只是不肯承认换轴。B 不是一个与 A 并列的选项，是 A 的不完整形态。
2. **我在核验中发现 v0.9 的键槽机制还有至少三个 codex 未指出的潜在缺陷**（下节），全部属于 ③ 同一族。逐条补丁不可能在 R8 前把这一族清零——codex R6→R7 已经实证「控制面开小处方→处方自身带新缺陷」的循环。唯一能一次关闭整族的是结构性改法，而 A 恰好是本 spec 家族已被 codex 判 CLOSED 的既有手法（契约 3 R4 换轴+锁内赋时+锁内折叠，R7 复核未破）。

## 一、③ 的裁定：A，且比备忘录里的 A 更小、更彻底

### 1a. 先坐实 codex ③（我重演出的最小分叉反例，5 事件）

到达序：`present h1@(t1)` → `absent@(t2)`〔e0 墓碑，removed〕→ `present h2@(t7)`〔门过，复活 e1〕→ **迟到 `absent@(t4)`**〔投影门外（t4<t7）不动投影，但 :354「读模型该纪元仍视其在场」成立 ⇒ 墓碑照写入流，键 `e1:absent:h2`〕→ **迟到 `present h3@(t3)`**〔门外，:348 照常入流键 `e1:h3`，不推进〕。

- 在线终态：epoch=1。
- 离线按 :352 全序重放 `(observedAt,id)`：P(t1), A(t2), **P(t3)→复活#1**, A(t4), **P(t7)→复活#2** ⇒ epoch=2。
- 分叉坐实；且 t7 行键嵌 `e1` 而重建判其应属 e2 ⇒ I-R1 误报隔离（数据没坏，是规则自己分叉）。注意反例的必要原料正是 :350/:354 的**迟到 absent 也照常入流**——所以 B 若只给 present 门做「重建模拟」，absent 侧同样分叉，规则数还得翻倍。

### 1b. 核验中新发现的三个 v0.9 潜在缺陷（均为键槽污染族，codex R8 大概率会挖到）

这三条全部从 :338 冻结的键格式直接推出，与 ③ 同根：

- **(i) 门外 absent 烧掉本纪元 absent 键槽 → 永久卡死 present**。上面反例里迟到 absent 已写入 `e1:absent:h2`；之后平台真删、爬虫产出真 absent（t8>t7，门过）→ 铸同键 `e1:absent:h2` → unique 去重吞掉 → 无新行、投影按「幂等成功」不动 → 本地永远 present。**24h 对账也修不了**：对账②「本地在场平台无→写 absent」铸的还是同一个键，永远被吞。平台已删、本地永远显示在场，直到内容变 hash 或纪元推进——两者都不会发生。
- **(ii) 门外 present 烧掉同 hash 键槽 → 显示永久陈旧**。迟到旧 present（h_old）按 :348 照常入流占掉 `e1:h_old`；日后平台内容真的改回 h_old（评价者撤销编辑），新观测铸同键 → 被吞 → 显示停在旧内容；对账③比的是「读模型 vs 流内最新观测」，流内根本没有这笔 ⇒ 盲区。
- **(iii) 同纪元 A→B→A 内容回摆被吞**（与迟到无关，纯键设计问题）：`e1:hA` 已存在，内容 A→B→回 A，第三笔铸 `e1:hA` → 去重吞掉 → 显示永远停在 B，对账同样盲。评价者「编辑后又改回去」是真实场景。

结论：**v0.9 的 unique 键同时承担了「重试去重」和「同纪元同内容只此一笔」两种语义，二者在乱序与回摆下互相打架**。逐条打补丁（B 路线）意味着给键格式再叠规则；A 路线下则整族消失（见 1c）。

### 1c. v1.0-③ 处方（A 的具体化——比备忘录版本更小：**零新时间戳列**，一条新原则）

1. **换轴**：投影全部状态（status/epoch/显示内容/lastX/quarantine 迁移）=对**已入流观测行**按**到达序**的单一确定性折叠 `fold`；在线=插入时同事务锁内折叠一步，离线重建=同一 `fold` 按到达序全量重放。恒等按构造成立，:348 那种逐场景「一致性论证」整体删除、不再需要。
2. **到达序载体**：per-`(ownerId, platform, externalReviewId)` advisory xact lock 序列化全程「取锁→读行态→判定→（可能）插观测→（可能）折叠写投影」；观测行加一列 **`arrivalSeq Int`（per-review 计数器，锁内自增自 ReviewItem）**，重建 `ORDER BY arrivalSeq`。不要用 ULID 或 clock_timestamp 当到达轴（ULID 锁外铸造可倒序；时钟可回摆）——整数计数器在锁内是无洞、严格单调、可向 founder 一句话解释的（「第几笔到达」）。六表尚未建（founder-only 单列待批），此刻加列零迁移成本；上线后再改就是大动作——**这是现在做 A 而不是上线后做 A 的决定性理由**。
3. **写入与生效耦合（新原则，一句话冻结整族）**：**「入流才需确定性；不入流只需留痕。」** `(observedAt,id)` 字典序高水位门保留，但改为**入流闸**：门外（陈旧）观测——present 与 absent 对称——**一律不入流**，记 `ActionEvent reputation.review.stale_observation_dropped {observedAt, contentHash, kind}` 留痕（按契约〇分账纪律，运营噪声本来就该走 ActionEvent，不该占观测账）；同内容 no-op（重爬未变）同样不入流。入流行的折叠效果=行与前序行的纯函数。此原则同时杀掉 codex ③ 与上节 (i)(ii)(iii)：陈旧观测不再烧键槽；A→B→A 第三笔因内容≠当前投影而正常入流（键含 arrivalSeq 必唯一）；重试去重由「锁内内容比对=no-op」承担，unique 键降为防御性护栏。
4. **CAS 赢家/输家规则全套删除**，由锁取代（锁内先到先折叠，后到者读到新态后按普通规则折叠自己那笔）。这是净删规则，不是加规则——给 codex 的文本面变小。
5. **epoch 语义改述**：从「(observedAt,id) 全序转换计数」改为「折叠态计数」（到达序下的 absent→present 生效转换数）。嵌键、I-R1（键 epoch==列 epoch）、fail-loud 隔离全部原样保留。

### 1d. 换轴对已冻结 v0.6 反例表的连带影响（备忘录点名的隐藏风险，逐条核过）

- v0.6 反例表（:338「首现 e0:h1→删 e0:absent:h1→同 hash 重现 e1:h1→二删 e1:absent:h1」）是**顺序到达**场景——到达序=逻辑序，折叠产出逐键相同，**该表原文逐行存活**，不需改判，只需在表头把「全序」两字换成「到达序」。
- 需**新增**验收行：codex ③ 的 5 事件反例（新判定：迟到两笔不入流→在线=重建=epoch 1）+ 上节 (i)(ii)(iii) 三场景。把对手的反例变成自己的验收行是收敛循环里最强的闭合信号。
- 对账三类漂移规则存活，且简化：对账补写=以拉取时刻为 observedAt 的普通观测，走同一把锁同一入流闸（observedAt=now 必过门），**不再是特殊路径**；并补第四类漂移「同为 present 而内容≠平台」——(iii) 修复后此类自然由普通入流承接，写一行点名即可。

## 二、④ 的裁定：并入 A 的锁，外加两件 codex 还没找到的事

1. **所有投影写路径共锁**：在线折叠、对账③重建、解除隔离全量重建，三者均在同一把 per-review advisory xact lock 内。**解除隔离=单事务原子**：`{取锁 → 全量重放折叠 → 写快照 → integrityStatus 复位 'ok' → 提交}`。备忘录里那个竞态（重建扫描后、复位前的新观测被谓词挡住且丢更新）按构造消失：并发摄入在锁上排队，等到时看到的已是 ok+新快照，正常折叠其上。隔离期间摄入=锁内「入流不折叠」，其积压由解除时重放消化——在 A 之下这不是补救流程，就是重建定义本身。
2. **「第 N 条写路径」用不变量关死，不用枚举**：冻结一句「`ReviewItem` 投影列唯二写入点=`fold`/`rebuild` 两函数，二者必持锁」+ 机器闸（CI grep 断言仓库内无第三处写投影列；可选加 DB 触发器查 `pg_locks` 断言持锁）。枚举永远数得漏，不变量+机械断言才是类闭合。
3. **主动预闭：ReviewItem 有第 4 个写者没人点过名**——:291 写明该表=「只读镜像**+回评态**」，`replyStatus/replyBody` 由 B8 回评流写入，**不是观测流投影**。「可全量重建」的宣称只对镜像列成立。v1.0 必须冻结**列所有权分区**：投影列（status/epoch/rating/body/lastX/integrityStatus）vs 运营列（replyStatus/replyBody）；`rebuild` 与冻写谓词**只作用于投影列**，运营列另有其锁（同一把 review 锁即可）且不受 quarantine 冻结（商家在数据核对期照样能起草回评）。不写这条，codex R8 第一个问题就是「重建会不会抹掉回评草稿」。
4. **隔离级别必须冻结 READ COMMITTED（PG 默认）**：REPEATABLE READ 下事务快照在**取锁语句开始时**已定格，锁等待结束后读到的仍是取锁前世界——「锁内读行态」整套协议静默失效。在并发主权总注加一行「本表全部锁协议假设 READ COMMITTED」，一并覆盖契约 3（其 R4 手法有同一隐含假设，单独去改它的章节反而可能重开已 CLOSED 项）。

## 三、⑤ 的裁定：登记式谓词保留，B 的修法方向对，但按原样写仍不 sound——须加四道冻结

**codex 的缺陷判定成立**：`nextval` 不触发 XID 分配（序列递增不随事务回滚，正因它不挂 XID——这也是空洞存在的原因）；即使单条 INSERT 里，default 求值（nextval）也先于 heap 写入（XID 在此才分配）。窗口极小但 spec 层面前提即假。

**B 的「XID-先于-nextval」论证在补齐以下四条后才真正 sound**（缺一条整链断）：

1. **强制点收进唯一写函数，不靠调用方纪律**。「transactional outbox 天然先有状态变更写」不可依赖——哪个 producer 先 insert outbox 再改状态、或某条 ops 脚本直插，soundness 就静默死。冻结：outbox 只可经单一 SQL 函数写入，函数体内 `PERFORM pg_current_xact_id()`（强制分配**顶层** XID，子事务/savepoint 下亦安全）**先于** `nextval`；`REVOKE INSERT` 直写权=机器闸。此后论证链成立：首见空洞 ⇒ 有可见行 seq''>s ⇒ nextval(s'') 已发生 ⇒（序列单调）nextval(s) 更早 ⇒（协议）其事务顶层 XID 更早已分配 ⇒ XID < 登记快照 xmax ⇒ `xmin ≥ xmaxAtFirstSeen` 真则该事务必已终结，仍无行=已回滚=真废。
2. **必须冻结 `CACHE 1`（并禁 `setval`/`ALTER SEQUENCE RESTART`）**——这是我方推演出的、B 原文没有的漏洞：CACHE>1 时后端本地缓存的序号可在**几分钟后**由另一个事务取用，「见洞 ⇒ 分配已发生于某事务」的前提整体崩塌（值被保留给 backend 而非事务），XID 协议救不回来。BIGSERIAL 默认 CACHE 1，但不写死就会被日后「性能优化」一行 ALTER 静默杀死。顺带写明：崩溃恢复/failover 的序列前跳=纯永久空洞，谓词正确处理。
3. **判废求值顺序冻结**：单次判定内取**一个**快照，用其 xmin 判条件(2)、用**同一快照**确认空洞仍在（行仍不可见）。xmin 用旧快照+缺行用更旧快照的组合不 sound；写死「同快照双判」。
4. **投递器重启丢登记表=保守重登记**（新 xmax 更大、只更晚判废，sound）——一句话写明，免得 codex 当缺口提。

**为什么不换成「无洞计数器表」（第四方案，已评估后降为备选）**：per-owner 计数器行 `UPDATE…RETURNING` 可整体删掉空洞机器（登记表、60s、xmax 推理全没了），确实更结构化；但 outbox 与业务状态变更**同事务**，行锁将把**同租户全部产事件业务事务互相串行**，且给每个业务事务加了第二把锁——正面违反 B2 自己刚冻结的「一事务一锁消死锁面」纪律。XID 协议保持 outbox 写入无锁。故：主案=XID 协议加固版；计数器表写进台账作为「若 R8 再破序列模型即切换」的预授权后手。

**B2:248 同步**：改为**引用不复述**——「seq 消费端语义与判废协议冻结于 B9 契约 6（登记式双条件+单写函数 XID 先取协议+CACHE 1）」，删掉行内复制的论证细节，杜绝下次两处漂移（本轮 B2:248 复制到的正是缺陷句）。

## 四、缺失证据（R8 前要补的）

1. **PG 版本与函数名**：`pg_current_xact_id`/`pg_current_snapshot`/`xid8` 需 PG≥13；仓库生产 PG 版本未在两 spec 内钉死。冻结函数名+`xid8` 类型+最低版本一行。
2. **在线折叠与观测插入是否同事务**：v0.9 隐含同事务（CAS「同一事务内插观测」），A 之下必须明写「插入+折叠同事务且同锁」。
3. **回评写者的完整列清单**（列所有权分区表的输入）：replyStatus/replyBody 之外 Testimonial 引用是否也落 ReviewItem——冻结时逐列点名。
4. **v0.6 反例表的冻结出处**：它随本 spec 版本化（同一文件、同一四权闭环在修），不涉外部已签冻结件；若曾单列入某 D-裁定，v1.0 冻结包里给 founder 一行点名「反例表表头换轴、行判定不变+新增四行」。

## 五、置信度与失败模式

- **③④ 方向（A 具体化）：高（~0.85）**。分叉反例与三个键槽缺陷都是从冻结文本直接机械推演的，不依赖实现猜测；A 是同族已过审手法的移植，且净删规则（CAS 全套、逐场景一致性论证）多于新增。主要残余风险=改写 §四点六·1 的文本面较大，codex 可能对新原则句（「入流才需确定性」）提措辞级质询——对策见下。
- **⑤（B 加固版）：中高（~0.8）**。XID 惰性分配、子事务顶层 XID、2PC 持 xmin、CACHE 语义均为 PG 文档级事实，我逐条推过；残余不确定在更冷僻的角落（逻辑复制下序列前跳已按永久空洞覆盖）。四道冻结缺一不可，R8 提交前逐条自查。
- **失败模式提醒**：若 codex R8 对「陈旧观测不入流」提出「观测账完整性」异议（append-only 教义直觉），回答已备好：陈旧/重复观测是**运营噪声**，按契约〇五账分层本就归 ActionEvent，不归观测账；观测账收录的是「生效观测」，其确定性投影承诺因此才能成立。这不是放宽 append-only，是把两种真相面分开记账——用他们已接受的宪法级分层来答。

## 六、R8 一次清零的操作纪律

1. **§四点六·1 整节重写为单一连贯块**，不再叠第六层补丁——现文本已是五层补丁互相引用，每层接缝都是 codex 的靶面；重写反而缩小攻击面。其余改动（B9 契约 6 四道冻结、B2:248 改引用、总注加 READ COMMITTED 行）保持外科手术式。
2. **验收表带上对手的弹药**：codex ③ 反例 + 本备忘录 (i)(ii)(iii) + 解除隔离并发场景 + A→B→A 回摆，每行给「在线=重建」双列判定。
3. **给 codex 的复审包附 diff 地图**：哪些行是净删（CAS/论证）、哪些是换轴改述（反例表表头）、哪些是新增（arrivalSeq、入流闸、列所有权、四道 ⑤ 冻结）——定向复审定向答。
4. **不主动开新战线**：GDPR 擦除 vs append-only、契约 3 的时钟回摆等已知未爆点**不进 v1.0 文本**，按既有惯例落假设台账；R8 的目标是清零 ③④⑤ 这一族，不是把 spec 写完美。
