# OVERVIEW

Hedra "Creation Studio" is an agentic creative workspace that turns a single conversational thread into a planning+execution loop over an infinite spatial canvas. The product's center of gravity is the "Space": a deep-linkable workspace (URL /app/space/{uuid}?chat={uuid}&agentView=canvas|grid) that fuses (a) a left-side conversational agent rail and (b) a right-side Figma/tldraw-style infinite canvas where every AI output lands as a first-class, manipulable node. The 11.4-minute walkthrough is a single Chinese-language session ("Greeting in Chinese", space d7cce60e…) by an operator who is benchmarking Hedra against their own product ("Studio · Fikirtive" tab open alongside). The session arc: orientation on the home dashboard → create a Space from "你好" → tour canvas primitives (text, Section containers, document cards, Library) → assemble an image+ElevenLabs-audio+NL prompt for a talking-head video → twice decline the agent's proposed render via natural-language denial → pivot to a multi-part image edit (clothes→blue, background→black) which runs to completion → request "make the man stand up" → agent self-corrects after a model/aspect-ratio failure, renders a 5s 3:4 image-to-video → user reviews inline, fullscreens, and fires a one-click 4K Upscale. The throughline and the moat: Hedra is a model-agnostic creative DIRECTOR agent. It compiles loose multilingual intent into structured, parameterized, credit-priced generation jobs; routes across ~38+ third-party models (image and video) by capability; exposes its full chain-of-thought as a timed step log; and NEVER spends compute without a human-in-the-loop "Generate" gate. The canvas is simultaneously the output gallery, the assembly/document surface, and the prompt-context source — selecting any asset feeds it back into the chat as a reference. Net positioning: not a model, not a chat toy, but an orchestration layer ("cowork") that makes a multi-vendor generation stack feel like one transparent, governable, spatial creative partner.

# UIUX PARADIGM

CORE PARADIGM: a dual-surface "agent + canvas" workspace, not a chat app and not a pure design tool — it is both, bound by shared state. Two macro-modes:

(1) HOME (/app/home): centered single-column — left nav rail (Hedra logo+collapse, New Space, Library, Search, Additional Tools, Help & Support, "Credits 1,122", Account) + hero ("Start with an idea" glyph/headline/subcopy "Describe your project and your agent will plan it out, create the assets, and tell you where to take it.") + a universal composer card (placeholder "Paste a link, drop a brief, or describe your idea…") + a "Your Spaces" project grid (cards with thumbnail, title, relative timestamp, hover-reveal "…" kebab → Rename/Delete).

(2) SPACE (/app/space/{uuid}): two-pane — LEFT ~33% conversational agent rail (back chevron, editable thread title, collapse icon, message stream, composer); RIGHT ~67% infinite dotted canvas OR a grid gallery, toggled top-right.

NAVIGATION/ROUTING — URL IS THE SOURCE OF TRUTH, hierarchically composed and deep-linkable: /app/home → ?chat={uuid} (a chat session mints first) → /app/space/{uuid}?chat={uuid} (Space binds to thread) → &documentShapeId=sh… (a focused/expanded shape) → &agentView=canvas|grid (active view). Spaces, threads, individual canvas shapes, and views are all independently addressable/back-forward-safe.

CANVAS UX: dark dotted infinite board; right vertical TOOL RAIL (select arrow [default], hand/pan, "T" text, marquee/region-select, document/page, shapes/node-connector, and an "Open Library" icon at bottom); top-right view toggles (grid/gallery + fit/aspect); bottom-right zoom control ("− %% +") with freeform steps (observed 5/10/15/18/19/25/30/32/44/47/54/62/64/84/100/112/114%). Selection = purple/blue bounding box + corner handles (mid-drag often renders red). Smart snapping = red alignment guides + center crosshair + equal-spacing distance ticks (Figma-grade). Cursors are semantic: arrow=select, grab=pan, crosshair=draw, I-beam=text, four-arrow=move, double-arrow=resize. Containers ("Section") nest children; parent/child re-selection toggles scope.

CHAT/AGENT UX: append-only auto-scrolling timeline. User bubbles carry attachment tiles (image thumbnail + audio player with ▶/scrub/duration) and copy+regenerate icons. Agent progress uses TWO stacked devices: (a) rotating single-word gerund "mood" status pills (Unfolding, Musing, Imagining, Crafting, Compositing, Drafting, Dreaming, Ideating, Composing, Ponderlusting, Wandering, Visualizing, Fluxing, Glimmering, Morphing, Worldbuilding) with a sparkle glyph; (b) a vertical accordion of named, timer-badged reasoning STEP rows (e.g. "Refining Animation Direction 6s", "Listed models", "Analyzing Lip Sync Models 2s") that auto-collapse on completion and expose verbatim chain-of-thought + inline monospace code chips (assets_analyze, generate_video, hedra_avatar, audio_id, Dialogue:"None"). Per-message feedback: thumbs-up/down/copy.

COMPOSER GRAMMAR (constant across home/space): toolbar "+" (add: Upload file / Take photo / Draw / Assets), "@" (mention/reference), a wand/magic-enhance icon, a slash "/" Skills/command picker (tooltip-confirmed "Skills"), and a state-driven send button: disabled-gray (empty) → active-white (text) → filled-square STOP (running) → circular up-arrow (idle). During a pending confirmation the placeholder swaps from "Tell me what you're working on…" to a secondary "or tell me what to do differently".

SIGNATURE COUPLING: selecting any canvas asset auto-attaches it as a thumbnail chip into the composer and enables send; deselecting removes it and dims send — the selected object IS the agent's working reference. Empty states are warm ("Nothing in this space yet. / Ask the agent to create anything you can imagine."). Tone throughout is friendly, multilingual (mirrors the user's Chinese), and reassuring.

# LOGIC/FRAMEWORK

THE COWORK AGENT IS A PLANNER / TOOL-ORCHESTRATOR with an explicit, observable state machine. Loop:

1. INTENT INTAKE (multimodal, multilingual) — parse NL turn + attached references. References arrive three ways: composer "+"/"@", file upload, or the signature CANVAS-SELECTION binding (selecting a node injects it as a composer chip). The selected/attached asset is the agent's grounding subject; assets are addressed by stable UUID (e.g. 81ac3edf-7893-…), so chat and canvas share ONE asset graph that tools consume by id.

2. PLAN + REASON (transparent) — decompose the goal into discrete, individually-timed sub-steps emitted as a streamed token trace grouped under auto-titled accordion rows, with rotating gerund mood labels as a presentation layer (NOT 1:1 backend stages). The trace exposes: tool deliberation (whether to call assets_analyze; skips it when the reference is already attached + instructions specific — a context-aware optimization), intent disambiguation (video-vs-still done in-reasoning, not as a blocking question), and validation/constraint-satisfaction (audio duration 112,744ms ≤ model max; aspect-ratio compatibility vs source 3:4).

3. MODEL ROUTING (capability registry) — query a structured multi-vendor catalog ("Found: 38 models") whose per-model attributes are use_case (lip_sync), supported paths (image_to_video / "start frame only"), max_duration, credits/sec or credits/gen, supported aspect ratios, and resolution tiers. The agent filters by task + input geometry, weighs cost/quality, and picks a default — but every field stays user-overridable. The UI re-derives valid dependent params on each change (model→resolution, aspect→resolution), preventing invalid configs.

4. PROMPT SYNTHESIS (template compiler) — translate loose CN intent → English, then template it into fixed labeled fields (video: Cinematography/Subject/Action/Context/Style&Ambiance/Dialogue/On-Screen Text/SFX; image: Subject/Composition/Action/Location/Style/Editing Instructions) with explicit identity-preservation language and negative constraints. API contracts are enforced here (Dialogue:"None" when audio_id present so audio, not text, drives lip-sync).

5. HUMAN-IN-THE-LOOP GATE (confirm-before-spend) — instead of auto-executing, emit a typed, editable, parameterized tool-call CARD and PAUSE at "Needs your input". The card is the unit of action. Branches: Generate (accept) / Skip (bypass) / edit-fields / NL redirect ("or tell me what to do differently"). A per-space "Always Ask vs Never ask" policy governs whether the gate appears at all — the autonomy dial. This is a credit-spend guardrail and a trust surface.

6. NL-AS-CONTROL-SIGNAL — during a pending card, a free-text reply is CLASSIFIED as accept/deny/modify. Denials are first-class, auditable events: dismiss card → append-only "User denied: '<verbatim>'" pill + "Video not generated" outcome → re-enter planning with the feedback as a new constraint → re-propose a regenerated card. Cancels abort with an "Acknowledging User Action" step + graceful confirmation, spending nothing.

7. EXECUTE (async, interruptible, self-correcting) — dispatch to a job queue; surface coarse polled progress (%) mirrored to chat + canvas via a shared job-state store keyed by asset/job id; allow STOP. On failure (model/ratio mismatch) the planner re-plans, re-routes, re-prompts, and explains — failure recovery is part of the loop, not a dead end.

8. LAND + ITERATE — outputs become first-class canvas nodes beneath their source (provenance), with per-asset actions (Edit/Upscale/Variations/Download) decoupled from re-prompting, and selection re-feeds the asset into chat. This closes the loop: generate → select result → describe next edit → regenerate.

STATE/MEMORY: per-space + per-chat persistence encoded in the URL; an append-only, timestamped, expandable decision log (denials, acknowledgments, steps) functions as conversation+audit memory; the canvas scene graph persists assets, transforms, z-order, grouping. The agent "learns the user" within-session by folding each NL critique into the next structured-prompt revision and by remembering reference provenance to skip redundant analysis.

# END-TO-END WORKFLOW

CANONICAL USER JOURNEY (start → finished, distilled from the session):

STEP 0 — ENTER: On /app/home, type/paste intent into "Start with an idea" (or open an existing Space card). Submit mints ?chat={uuid} then navigates to /app/space/{uuid}. The two-pane workspace materializes; the agent auto-titles the Space from the prompt.

STEP 1 — GROUND THE TASK: Bring source material into context via any of: composer "+" → Upload file (OS picker), "@" mention, drag from the Library panel onto the canvas, or — the signature move — click a canvas asset so it auto-attaches as a composer thumbnail chip. Mixed references are allowed in one turn (e.g. portrait image + ElevenLabs MP3, which renders as an inline audio player).

STEP 2 — STATE INTENT IN NATURAL LANGUAGE: Type a plain instruction in your own language (Chinese here): "make the old man lip-sync to this audio" / "change his clothes to blue, background black" / "make the man stand up". Send (STOP appears = run started).

STEP 3 — WATCH THE AGENT PLAN (transparent): The agent streams a timed step log + gerund mood pills, exposing its reasoning: it disambiguates intent, decides which tools to call (skipping assets_analyze when context suffices), queries the model registry, filters by capability (use_case, supported path, aspect, duration, cost), validates constraints (audio length ≤ model max; aspect compatibility), and compiles your loose ask into a structured field-labeled prompt with identity-preservation.

STEP 4 — REVIEW THE GATED CARD: Instead of auto-spending, the agent pauses at "Needs your input" and renders an editable "Generate Image/Video" card pre-filled with model + aspect + resolution + duration + the structured prompt + a credit cost. You can: inspect/edit any pill (dependent params auto-re-derive), edit the prompt text, change the per-space "Always Ask" autonomy policy, click Skip, click Generate, or type a free-text redirect.

STEP 5 — STEER VIA NL (optional, repeatable): Typing into "or tell me what to do differently" is treated as accept/deny/modify. Denials log a verbatim "User denied" audit pill + "Video not generated" and loop the feedback back into a regenerated card; cancels abort gracefully with zero spend. (In-session the user denied two video proposals before the agent's plan converged.)

STEP 6 — COMMIT: Click Generate. The card collapses; an async job enqueues (Queuing → % → reveal), mirrored as a tile in chat AND a node on the canvas placed beneath its source. STOP allows cancellation. If the job fails (e.g. model can't do the source's 3:4), the agent self-corrects: re-routes to a compatible model, re-authors the prompt, explains the switch, and re-runs — all without you re-prompting.

STEP 7 — RECEIVE + REVIEW: The result lands inline. Images paint into the chat thumbnail + canvas node; videos become an inline player (poster=first frame, duration badge, scrubber, quality ladder, native fullscreen with ±10s/speed/PiP). Hover the result to inspect/copy the exact auto-authored prompt. Rate it (thumbs up/down/copy).

STEP 8 — REFINE / POST-PROCESS: Use per-asset actions decoupled from re-prompting — Edit video, Create variations, Upscale (1080p/2K/4K → spawns a new billed job), Download. OR select the result (re-attaching it to chat) and describe the next edit — closing the iterative loop.

STEP 9 — ASSEMBLE: Arrange source + variants + results on the canvas; drop them into a "Section"/document with snap-aligned before/after layouts; the canvas doubles as the composition/deliverable surface. The agent auto-stages an empty placeholder for the next output.

Net: vague multilingual ask → grounded reference → transparent plan → capability-routed, structured, credit-priced, human-gated job → async mirrored execution with self-correction → inline reviewable output → one-click refine + spatial assembly.

# DESIGN PRINCIPLES

THE MOAT — design principles that define Hedra "cowork" and are hard to copy:

1. ORCHESTRATION OVER MODEL. Hedra's value is NOT a model — it's the director layer that makes a 38+-model, multi-vendor stack (OpenAI, Google, ByteDance, Black Forest Labs, xAI, Alibaba, Kuaishou, MiniMax, VEED + first-party Hedra Avatar/Character 3) behave like ONE coherent creative partner. Capability-aware routing + dependent-param gating means the user never has to know which model does 3:4 lip-sync at what cost — the agent does. This abstraction, the registry that powers it, and the integrations behind it (incl. ElevenLabs, BytePlus) are the durable asset.

2. INTENT-TO-STRUCTURE COMPILATION. The agent's core trick is turning a sloppy, multilingual one-liner into a disciplined, field-labeled, identity-preserving generation contract (Cinematography/Subject/Action/… ; Subject/Composition/Editing Instructions/…). This prompt-engineering-as-a-service — including enforcing real API constraints (Dialogue:"None" w/ audio_id) and folding NL critique into specific field edits — is what makes amateur input produce professional output.

3. TRANSPARENCY AS TRUST. The full chain-of-thought is the product, not a debug view: named, timed, collapsible steps + verbatim tool names + visible model-comparison reasoning + hover-to-inspect final prompts. Users SEE the agent reason, route, validate, and even fail-and-recover. This builds trust in an inherently nondeterministic, money-burning process and turns latency into legible progress.

4. CONFIRM-BEFORE-SPEND, WITH A DIAL. Every expensive generation is a human-gated, editable card ("Needs your input"); compute is never silently spent. The per-space "Always Ask vs Never ask (autonomous)" policy lets the user move along the autonomy spectrum on their own terms. Credit cost is surfaced inline at the decision point. This is governance + cost-control as a first-class UX, essential for a credit-metered SaaS.

5. NATURAL LANGUAGE AS THE UNIVERSAL CONTROL. You steer entirely by talking — accept/deny/modify are all just NL, classified by the agent, with denials/cancels captured as auditable first-class events that re-enter planning. No mode-switching, no form-wrangling required; the buttons are a convenience, not a requirement.

6. SPATIAL CANVAS AS THE SUBSTRATE, NOT A CHAT LOG. Outputs are durable, manipulable nodes on an infinite board (Figma-grade snapping, containers, documents), placed beneath their sources for provenance, assemble-able into deliverables. The canvas is simultaneously gallery, workspace, and — via select-to-reference — the prompt-context source. This bidirectional chat↔canvas binding (the selected asset IS the working reference) is the signature "cowork" primitive and the hardest interaction to clone well.

7. ITERATION IS THE FIRST-CLASS LOOP. Reference-conditioned, identity-locked editing + select-result-then-describe-next-edit + per-asset Variations/Upscale/Edit (decoupled from re-prompting) make refinement, not one-shot generation, the default mode — matching how real creative work actually happens.

# RISKS
RISKS in mapping Hedra → Fikirtive's Next.js/fal stack (grounded in the actual repo):

1. CAPABILITY GAP — NO AUDIO/VOICE/LIP-SYNC (highest). Hedra's hero flow (talking-head, ElevenLabs voice-clone, lip-sync via omnimodal Character-3) has ZERO analog in Fikirtive. Confirmed by grep: no lip-sync/elevenlabs/tts/talking-head/avatar references anywhere in apps or packages; the only "audio" in the codebase is (a) a per-model native-audio on/off toggle on video gen (GEN_VIDEO_MODEL_INFO.sound) and (b) Shotstack/Pixi audio clips in the video editor. Fikirtive's fal lineup (gen.ts: seedream image; kling/veo/ltx/seedance/wan/pixverse/grok/hailuo video) has no avatar/lip-sync model. RISK: if the Fikirtive cowork is benchmarked feature-for-feature against this walkthrough, the centerpiece is un-buildable on the current stack — scope must explicitly exclude lip-sync or add a new fal avatar model + audio-ingest pipeline (large, not a "skill"). Recommend de-scoping the talking-head arc and cloning the ORCHESTRATION pattern (plan→propose→gate→generate→review) on image/video Fikirtive already has.

2. PARADIGM INVERSION — MODEL ROUTING. Hedra: agent auto-selects the model. Fikirtive: user picks the model in GenSpace's settings panel; the cowork agent does no routing (cowork-transport.ts routes only to one Claude LLM for text skills; gen-actions.ts takes model from the client request). The masterplan's knowledge base (ModelDirective, keyed family×mode) tunes PROMPTS per model but does NOT pick the model. RISK: cloning Hedra's auto-router is a new capability (a routing skill that reads GEN_VIDEO_MODEL_INFO/OPTIONS capabilities and chooses), not a prompt tweak — and it collides with the existing user-picks-model UX. Must decide: agent-suggests-overridable vs agent-decides.

3. NO CONVERSATIONAL THREAD EXISTS. Hedra IS a chat thread with an append-only message stream + streaming chain-of-thought step log + rotating mood pills. Fikirtive cowork is stateless one-shot server actions (coworkDraftStoryboard, enhancePrompt) invoked from buttons; no Message/ChatThread DB model, no streaming (transport.chat returns one {text}, gen runs async via pg-boss + client polling, not SSE/streaming). RISK: the agent+canvas dual-surface requires net-new infrastructure — a persistent thread data model, a streaming transport (current FalTransport is single-shot fetch→{text}, not token-streamed), and an inline progress UI. This is a foundational build, far beyond the masterplan's "add a skill = one directory" framing. The masterplan's Skill/runSkill spine is reusable but the conversational shell is not yet designed.

4. MONEY-SAFETY UNDER AUTONOMY. Fikirtive's money-safety is strong but built for USER-INITIATED single spends: mock-default unless FAL_KEY; validate-before-spend; double-submit guards (busyRef synchronous mirror + idempotencyKey + partial-unique index); poll-timeout marks jobs non-retryable to avoid double-charge; Guardian blocks broken-ref renders pre-spend. RISK: Hedra's agentic loop implies the AGENT proposes spends. If Fikirtive's agent ever auto-dispatches startGen (cf. masterplan Phase 4 fillStoryboard fanning N jobs), every existing guard assumes a human clicked once — an agent loop could fan-out, retry, or re-propose and multiply spend. The "NEVER spend without human gate" is the exact invariant to preserve, but the current guards are per-click, not per-agent-turn. Any cowork-initiated generation MUST route through the same human-gated startGen, never a new agent-only path, or money-safety regresses. (Memory confirms a prior real-money double-spend incident across all entry points — this is a live concern.)

5. CANVAS SUBSTRATE MISMATCH. Fikirtive's Canvas.tsx is the ONLY mock surface (Studio.tsx comment: "Canvas is the only mock surface") — there is no real infinite-canvas/tldraw implementation, no shape persistence, no node data model. Hedra's canvas is first-class (every output is a manipulable node, deep-linked by shapeId). RISK: cloning the canvas is a from-scratch build (tldraw integration + persistence + the select-asset-as-reference coupling), not an enhancement. Fikirtive's current surfaces are tab-based (GenSpace/Storyboard/Editor/Elements/Assets via StudioShell nav), a fundamentally different IA than Hedra's two-pane agent+canvas.

6. REFERENCE-LAYER SEMANTIC MISMATCH. Hedra's "select asset → it becomes the chat reference" is raw-asset-keyed. Fikirtive's reference layer is ENTITY-keyed (@mention entities with base+named-variants, e.g. @mira:red-dress — see the just-shipped Phase A/B/C reference-base-variants work). RISK: these are genuinely different models. Mapping Hedra's loose "selected image = context" onto Fikirtive's structured entity/variant system is a design decision, not a copy — and Fikirtive's entity layer is actually a DIFFERENTIATOR worth preserving rather than flattening to Hedra's asset-blob model.

7. SCOPE/DECOMPOSITION. The teardown bundles ~20 features (canvas primitives, library, agent core, routing, gate, upscale, audio, multilingual, deep-links). RISK: treating "build cowork like Hedra" as one project. The repo's own masterplan already decomposes the AGENT half into Phases 0-4 (foundation→enhance→guardian/coach→shotDoctor/recipe→fillStoryboard) with money-risk-last sequencing. The CANVAS half and the CHAT-THREAD shell are NOT in that plan at all. A Hedra-parity effort silently triples the masterplan's scope.

8. STREAMING CHAIN-OF-THOUGHT IS UNVERIFIED + POTENTIALLY MISLEADING TO CLONE. Research flags the timed step-log + verbatim tool-name/param exposure as video-only/unconfirmed and warns reviewers tested different product generations. RISK: building elaborate "expose the agent's reasoning steps with timers" UI on the assumption Hedra does it could be cloning a one-session artifact, and exposing verbatim tool/param chains (assets_analyze, hedra_avatar, audio_id) may not be desirable for Fikirtive (leaks model/provider internals).
